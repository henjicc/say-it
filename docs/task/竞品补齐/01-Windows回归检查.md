# Windows 回归检查

「选区编辑」没有选区时改上一次输入，是在 Mac 上写的。Windows 专属分支（等修饰键松开的 `hotkey::modifier_held`）在 Mac 上无法交叉编译检查，Windows 上也没有真机运行过。在 Windows 上开工时按本清单逐项检查，全部完成后在文件开头注明「已完成」。

- [ ] `npm run check` 通过（确认 `hotkey.rs` 的 `modifier_held` 和 `assistant.rs` 的 `wait_modifiers_released` 能编译）。
- [ ] 记事本里听写一句话，不选中任何文字，按「选区编辑」快捷键（含 Ctrl 的组合），按住说「改正式一点」后松开：上一次输入的文字被替换成改写结果，其余内容不变。
- [ ] 同上，但用单击触发模式：说完再按一次快捷键结束，结果同样正确，光标没有跳到词边界。
- [ ] 快捷键含 Alt 时，触发后键盘布局（输入法）没有被切换。
- [ ] 听写后把光标挪到别处再触发：提示「上次输入后光标已移动」，原文和光标位置都不变。
- [ ] 浏览器里听写后点一下页面空白处（焦点离开输入框）再触发：提示「请先选中需要修改的文本」，页面没有滚动或翻页。
- [ ] 改写进行中按取消：程序选中的上一次输入可能保持高亮（取消时无法收起），确认这在实际使用里是否需要处理。
