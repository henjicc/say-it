# 原生窗口框架：Windows 回归检查

本任务在 macOS 上完成，Windows 代码没有在本机编译和运行过。到 Windows 真机后按顺序检查，全部通过后在本文件标注「已完成」。

涉及的改动：
- 窗口声明 `OverlaySpec` 与通用宿主（`native_win/host.rs` 改为直接消费声明，窗口类名变为 `sayit-native-indicator` / `-orb` / `-subtitle`）。
- 共用组件层 `overlay-core/src/ui`，胶囊、悬浮球、字幕条改用其中的面板绘制、音量柱、拖动阈值与坐标换算；胶囊的指针层换成 `UiPointer`。
- 新窗口：会议录制条（`sayit-native-recorder`）。
- 开发者页「原生窗口测试」面板（`desktop/native_test.rs`），用假数据摆出各窗口的状态。
- 悬浮球外观改为与胶囊一致的单色风格，「完成」「出错」改用线条图标。
- 胶囊与通知合成同一块面板，任意两个状态之间切换都有过渡。

只在 macOS 上生效、Windows 不用查的改动：屏幕信息到位后才创建窗口、按窗口所在屏改正缩放、拖拽期间不重摆窗口位置（都在 `overlay-macos`）。

## 3. 听写胶囊

- [ ] 录音、处理中、智能处理、兜底通知各状态显示正常，位置在主屏工作区底部居中。
- [ ] 任意两个状态之间切换都有过渡：面板宽度平滑变化，波形、点阵与通知的图标文字交叉淡化；从隐藏直接弹出通知时不带尺寸动画。
- [ ] 录音中带着实时文字时出现「已复制，请手动粘贴」或错误通知：文字框带着文字一起淡出，不是先变成空框。下一次语音输入开始时文字框是空的，不残留上一次的文字。
- [ ] 一条通知还在显示时来了更长的一条：面板从旧宽度长过去，新文字不会画到面板外面。
- [ ] 智能处理中：鼠标移到胶囊上变手形并显示「直接输入」，移开恢复；点击后立刻变为处理中并直接输出原文；点胶囊外不触发。
- [ ] 智能处理中把鼠标快速移出胶囊（从边缘直接移到窗口外），悬停效果消失。
- [ ] 其余状态点击穿透，能点到胶囊下面的窗口。
- [ ] 智能处理中把鼠标停在胶囊上不动，等它自己结束；下一次智能处理时再移上去，悬停效果仍然出现。

## 4. 悬浮球

- [ ] 显示、隐藏、各相位外观正常，风格与胶囊一致；「完成」是对勾、「出错」是红色警告三角；录音时五根音量柱随声音变化。
- [ ] 把悬浮球和胶囊摆在一起对比：底色深浅和描边亮度看起来是同一套。Windows 上带透明度的颜色会比 macOS 暗一些，留意「空闲」的图标、「已取消」的叉和转圈的底环是否暗到看不清；看不清就把对应的亮度调高。
- [ ] 悬停时描边和图标提亮，移开恢复，过渡不跳变。
- [ ] 完成后可提交时右下角的角标是浅色圆加深色箭头，悬停变成回车箭头。
- [ ] 悬浮球创建后拖动几次，大小不变。（越拖越大是 macOS 上的缺陷，Windows 不受影响，这里只确认没有回归。）
- [ ] 单击开始和停止，右键菜单，拖动后松手位置被记住，重启后还在原处。
- [ ] 拖到另一块缩放不同的屏幕，大小跟着变，不模糊。

- [ ] 在「转写 → 会议」点开始录制：屏幕顶部居中出现录制条，红点、计时每秒走、麦克风和电脑声音两组音量柱随声音变化。
- [ ] 按住条身拖动到别处松手；停止后再开始录制，条出现在上次的位置。
- [ ] 把条拖到副屏，拔掉副屏（或改成只用主屏）后再开始录制，条回到主屏顶部居中。
- [ ] 鼠标移到停止按钮上变手形、按钮有底色；点击后条消失，胶囊位置弹出「会议录音已保存，正在识别」。
- [ ] 开始录制后关掉主窗口（退到托盘），用录制条停止：录音保存在会议录音文件夹，重新打开主窗口，「文件」页能看到这次识别的进度或结果。
- [ ] 主窗口开着时用录制条停止：会议页的按钮在一两秒内变回「开始录制」，「文件」页接上识别任务。
- [ ] 录制中拔掉麦克风（或禁用录音设备）：对应那一路的图标和音量柱变成黄色，红点变黄。
- [ ] 混合缩放的两块屏之间拖动录制条，大小和清晰度正常。
- [ ] 录制条的底色、描边与胶囊一致；计时文字、图标和音量柱清晰，不发虚。

## 7. 开发者页「原生窗口测试」

用它过一遍上面各窗口的外观和手感最快：主窗口 →「开发者」→「原生窗口测试」。

- [ ] 每个窗口一排状态按钮，点哪个显示哪个，一次只摆出一个窗口；点别的窗口的按钮时前一个自动收起，新窗口的波形和逐字文字照常在动。
- [ ] 四个窗口的每个状态都能显示，录音状态有波形和逐字出现的文字，字幕逐字追加并滚动。
- [ ] 点已选中的按钮会重新摆一次（通知消失后可以这样重看）；点「收起」后测试窗口消失。
- [ ] 测试中点悬浮球、点字幕条的关闭、点录制条的停止，都不会开始语音输入、停字幕或停会议；点完悬浮球仍能再次点中。
- [ ] 点悬浮球的状态按钮和「收起」时主窗口不卡死（这两个命令在 Windows 上走异步派发）。
- [ ] 把悬浮球拖走后点「收起」：启用了悬浮球的回到原来的位置和空闲状态，没启用的消失。
- [ ] 测试窗口开着时按快捷键开始真实的语音输入：测试窗口全部收起，真实胶囊正常出现，结束后悬浮球状态正常。

- [ ] 选完一个状态后立刻切到开发者页的其他子页：测试窗口应被收起，不残留。
- [ ] 启用悬浮球时，测试过悬浮球后按快捷键开始语音输入：悬浮球显示录音状态，不停在空闲。
- 已知：测试中点了字幕条的「锁定」，下次真实字幕开始时字幕条仍是锁定的，再点一次解锁。
