# 原生窗口框架：Windows 回归检查

本任务在 macOS 上完成，Windows 代码没有在本机编译和运行过。到 Windows 真机后按顺序检查，全部通过后在本文件标注「已完成」。

涉及的改动：
- 窗口声明 `OverlaySpec` 与通用宿主（`native_win/host.rs` 改为直接消费声明，窗口类名变为 `sayit-native-indicator` / `-orb` / `-subtitle`）。
- 共用组件层 `overlay-core/src/ui`，胶囊、悬浮球、字幕条改用其中的面板绘制、音量柱、拖动阈值与坐标换算；胶囊的指针层换成 `UiPointer`。
- 新窗口：会议录制条（`sayit-native-recorder`）。

- [ ] 录音、处理中、智能处理、兜底通知各状态显示正常，位置在主屏工作区底部居中。
- [ ] 智能处理中：鼠标移到胶囊上变手形并显示「直接输入」，移开恢复；点击后立刻变为处理中并直接输出原文；点胶囊外不触发。

- [ ] 智能处理中把鼠标停在胶囊上不动，等它自己结束；下一次智能处理时再移上去，悬停效果仍然出现。

## 6. 会议录制条（新）

- [ ] 在「转写 → 会议」点开始录制：屏幕顶部居中出现录制条，红点、计时每秒走、麦克风和电脑声音两组音量柱随声音变化。
- [ ] 按住条身拖动到别处松手；停止后再开始录制，条出现在上次的位置。
- [ ] 把条拖到副屏，拔掉副屏（或改成只用主屏）后再开始录制，条回到主屏顶部居中。
- [ ] 鼠标移到停止按钮上变手形、按钮有底色；点击后条消失，胶囊位置弹出「会议录音已保存，正在识别」。
- [ ] 开始录制后关掉主窗口（退到托盘），用录制条停止：录音保存在会议录音文件夹，重新打开主窗口，「文件」页能看到这次识别的进度或结果。
- [ ] 主窗口开着时用录制条停止：会议页的按钮在一两秒内变回「开始录制」，「文件」页接上识别任务。
- [ ] 录制中拔掉麦克风（或禁用录音设备）：对应那一路的图标和音量柱变成黄色，红点变黄。
- [ ] 混合缩放的两块屏之间拖动录制条，大小和清晰度正常。

## 7. 开发者页「原生窗口测试」

用它过一遍上面各窗口的外观和手感最快：主窗口 →「开发者」→「原生窗口测试」。

- [ ] 四个窗口的每个状态都能显示，录音状态有波形和逐字出现的文字，字幕逐字追加并滚动。
- [ ] 测试中点悬浮球、点字幕条的关闭、点录制条的停止，都不会开始语音输入、停字幕或停会议；点完悬浮球仍能再次点中。
- [ ] 选悬浮球的状态和「不显示」时主窗口不卡死（这两个命令在 Windows 上走异步派发）。
- [ ] 把悬浮球拖走后点「全部收起」：启用了悬浮球的回到原来的位置和空闲状态，没启用的消失。
- [ ] 测试窗口开着时按快捷键开始真实的语音输入：测试窗口全部收起，真实胶囊正常出现，结束后悬浮球状态正常。
- [ ] 测试窗口开着时关掉主窗口：测试窗口在一两秒内全部收起。
