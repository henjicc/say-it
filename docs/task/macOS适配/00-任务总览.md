# macOS 适配：任务总览

分析基于 `main`（`4434ec0` 之后）与一台 Apple Silicon Mac（macOS 27.0，仅装 Command Line Tools，未装完整 Xcode）。

## 结论

macOS 不是从零开始：主流程（听写、实时字幕、录音识别、智能处理、上下文感知）在 Mac 上都有对应实现，README 标为「预览支持」。剩下的工作分三类：

1. **验证链路断了**：CI 的 macOS 任务从 2026-11-08 起一直失败，主程序的 Mac 测试实际没在跑；发布页也从未有过 dmg。
2. **有明确的功能缺口**：原生悬浮窗（悬浮球、字幕条是空桩，胶囊默认关闭）、本地整理模型、硬件检测、原生提示音。
3. **体验与工程收尾**：权限引导、菜单栏图标、文档与脚本。

## 适配工作清单

### A. 先恢复验证链路

**A1. CI 的 macOS 任务修绿**

- 现状：`verify (macos-15)` 在「Test overlay crates」步骤失败，`sayit-overlay-macos` 的两个用例不过：
  - `hosts::indicator::tests::cg_renders_all_indicator_states_inside_their_visible_panels`
  - `hosts::indicator::tests::cg_clips_overflowing_text_to_the_text_box_and_keeps_the_tail_visible`
- 根因：`8be36e6`（听写胶囊重设计）改了 `overlay-core/src/indicator.rs` 的尺寸与布局，Mac 侧用例里写死的面板矩形（如 `Rect::new(146.0, 124.0, 314.0, 164.0)`）还是旧设计。最后一次成功是 `c36f0e6`。
- 影响：这一步排在 `npm run test:rust` 之前，失败后主程序的 Mac 测试不再执行，之后 70 多次提交在 Mac 上没有任何自动验证。
- 要做：按新胶囊模型核对 Mac 绘制是否正确（是用例过期还是真的画错了，要看渲染结果判断），再更新用例。

**A2. 本机跑 Rust 测试的环境**

- 现状：`scripts/run-tauri.mjs` 会自动设置 `OPUS_LIB_DIR` 和 `MACOSX_DEPLOYMENT_TARGET=15.5`，`scripts/run-rust-tests.mjs` 不会。本机没有 `pkg-config` 时，`audiopus_sys` 找不到 Homebrew 的 Opus，转去源码编译，又缺 `autoreconf`，构建失败。
- 要做：把这段 Mac 环境准备抽成两个脚本共用的一份，`test:rust` 与 `tauri:dev` 行为一致。

**A3. 主程序在 Mac 上的测试结果**

- 现状：设好 `OPUS_LIB_DIR` 后主程序能在本机编译，764 个测试全部通过，说明 CI 停摆期间的提交没有破坏 Mac 的编译和单元测试。失败的只有 A1 那两个用例。
- 主程序有 13 条未使用代码的警告，大多是原生悬浮窗在 Mac 上还没接通的入口：`native_mac::ensure_started`、`native_mac/orb.rs` 与 `subtitle.rs` 的 `on_action`、`native_orb.rs` 的 `run_orb_action` 等、`dictation::skip_smart_processing`。它们会随 B1 消失；另有 `src/prelude.rs` 的两个未使用导入。
- 要做：A1 修好后确认 CI 的 `npm run test:rust` 在 `macos-15` 上重新跑起来。

**A4. 发布**

- 现状：`release.yml` 已有 `build-macos` 并要求 3 个资产，但最新发布 `v0.4.0` 只有 `SayIt_0.4.0_x64-setup.exe`，Mac 流水线还没有真正出过包。README 写的是「暂无签名发布包」。
- 没配 Apple 签名 secrets 时流水线出的是 ad-hoc 签名包，普通用户下载后会被 Gatekeeper 拦截。
- 要做（需要你决定）：是否用 Developer ID 证书签名并公证。要的话需配置 6 个 secrets：`APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`、`KEYCHAIN_PASSWORD`、`APPLE_ID`、`APPLE_PASSWORD`、`APPLE_TEAM_ID`。
- 要做：本机先完整跑通一次 `npm run tauri:build -- --bundles app dmg`，确认 `validate-macos-bundle.mjs` 通过。

### B. 功能缺口

**B1. 原生悬浮窗**

- 现状：三个悬浮窗在 Mac 上默认都走 WebView（`desktop/native_common.rs` 的 `PLATFORM_DEFAULT = cfg!(windows)`）。
  - 听写胶囊：原生实现已接通（`crates/overlay-macos/src/hosts/indicator.rs`），默认关闭，需 `SAYIT_NATIVE_INDICATOR=1` 才启用；胶囊重设计后未在 Mac 上验证（见 A1）；不支持点击跳过智能处理（面板始终点击穿透）。
  - 悬浮球：`hosts/orb.rs` 与 `desktop/native_mac/orb.rs` 是空桩。
  - 字幕条：`hosts/subtitle.rs` 与 `desktop/native_mac/subtitle.rs` 是空桩。
- 要做：胶囊真机验证后改为默认开启；实现悬浮球与字幕条的 Mac 宿主（模型、布局、绘制都在 `overlay-core`，只差宿主和桥）；胶囊接通指针以支持点击跳过。
- 改之前先读 `docs/rules/原生悬浮窗开发约定.md`。

**B2. 本地听写整理模型（llama.cpp）**

- 现状：只支持 Windows，共 6 处：
  - `scripts/build-llm-engine.mjs`：非 Windows 直接跳过；
  - `src-tauri/llm-engine/Cargo.toml`：`llama-cpp-sys-2` 只在 `cfg(windows)` 下依赖，且固定 `vulkan`；
  - `src-tauri/llm-engine/src/main.rs`：非 Windows 的 `main` 直接报错退出；
  - `src-tauri/src/main.rs`：推理程序路径只在 `cfg(windows)` 下配置；
  - `src-tauri/src/providers/plugin.rs`：安装整理模型包时非 Windows 直接拒绝；
  - `src-tauri/tauri.macos.conf.json`：`externalBin` 没有 `sayit-llm`。
- 要做：Mac 上用 Metal 构建 `sayit-llm`，作为 sidecar 打进包并签名，放开上述限制；重新实测加载耗时与内存占用。

**B3. 硬件检测与本地模型推荐**

- 现状：`application/setup.rs` 的 `hardware_summary()` 在非 Windows 返回空值，界面把这台 Mac 当成「硬件未知」：
  - 引导里本地识别默认落到 Fun-ASR-Nano，不会推荐 Qwen3-ASR，尽管 Mac 上 transcribe.cpp 能用 Metal；
  - 引导「本地优先」仍列出本地整理模型，但在 Mac 上安装必然失败（B2）；
  - `ui/src/features/models/localModelNeeds.ts` 的说明是「占约 3.5 GB 显存，需要独立显卡」，不适用于统一内存的 Apple Silicon。
- 要做：Mac 上读取内存与芯片信息，给出适合统一内存的判断和文案；B2 完成前在 Mac 上隐藏本地整理模型。

**B4. 提示音**

- 现状：`desktop/cue_player.rs` 的原生同步播放只有 Windows 实现，Mac 返回 `false` 后回到 WebView 播放（`ui/src/lib/cues.ts`）。
- 要做：真机确认 WebView 播放的延迟和「提示音占用输出设备」相关设置是否可接受，再决定是否做 Mac 原生播放。

**B5. Apple 系统语音没有进引导**

- 现状：`shared/asr-models.json` 有 `apple-speech-transcriber-live`，但 `ui/src/features/onboarding/setup.ts` 的 `ASR_CHOICES` 里没有它。
- 要做（需要你决定）：是否在 Mac 的引导里把它作为免下载的本地选项。

### C. 体验与工程收尾

**C1. 权限引导不完整**

- 现状：引导和初始化检查只看「辅助功能」（`application/setup.rs` 的 `permission_check`）。实际还需要：
  - 输入监控：Caps Lock 快速响应、鼠标手势（缺失时只在启动监听失败后报错）；
  - 麦克风；
  - 屏幕与系统音频录制：系统音频字幕、窗口 OCR。
- 要做：把这几项权限的状态和授权入口放进引导与设置，缺失时给明确提示。开发版与安装版是两个不同的授权主体，需要分别授权。

**C2. 菜单栏图标**

- 现状：托盘直接用应用图标（`main.rs` 的 `app.default_window_icon()`），不是模板图标，在菜单栏里不会跟随深浅色。
- 要做：真机确认观感，需要的话准备单色模板图标。

**C3. 仅 Windows 的工程设施**

| 设施 | 位置 | Mac 现状 |
|---|---|---|
| 空闲内存回收 | `application/idle_reclaim.rs` | 无，需实测常驻内存后再定 |
| 栈溢出取证 | `stack_diagnostics.rs` | 空实现 |
| 悬浮窗像素快照回归 | `desktop/native_win/snapshot/` | 无，Mac 只有 CG 离屏断言 |
| 性能测试（`performance_tests`） | 多处 `#[cfg(all(test, windows))]` | 不在 Mac 上跑 |
| 延迟截图 OCR | `active_app_context/mod.rs` 的 `DeferredOcr` | Mac 走立即截图 |

**C4. 系统版本与构建要求**

- 最低系统 macOS 15.5，受内嵌的 ONNX Runtime 限制。
- Apple 新语音引擎需要用 macOS 26 SDK 构建，CI 以 `--require-sdk-26` 卡住。
- 构建需要 `brew install opus`。

**C5. 文档**

- `AGENTS.md`：开发者追踪的数据目录只写了 Windows 路径；`docs/rules/原生悬浮窗开发约定.md` 的验证命令是 PowerShell 写法。
- `README.md`：Mac 的安装、权限、从源码构建说明要随 A4、C1 更新。

## 建议顺序

1. A1、A2、A3：先让 Mac 的自动验证恢复，否则后面的改动没有回归网。
2. 真机跑一遍 `tauri:dev`，按功能清单过一遍，补出只有运行才能发现的问题。
3. B1（胶囊默认开启 → 悬浮球 → 字幕条）、B2、B3。
4. A4 发布签名，C 类收尾。
