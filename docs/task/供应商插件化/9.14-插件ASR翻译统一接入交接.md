# 9.14 插件 ASR / 翻译统一接入交接

## 结论

Say-It 的 JavaScript 供应商插件只接受 Plugin API v5。ASR（文件与实时）和 translation 不再由业务路由直接调用一套独立协议，而是由一个宿主适配器注册进 `@henjicc/ai-sdk` 的真实 `CapabilityClient`；插件仍实现轻量 `invoke` / `realtime*` ABI，不需要也不允许打包 SDK。内置百炼 / Groq 路由不属于本任务。

本任务分三个独立提交：

- `7f5a1bc`：v5 capability 注册核心、QuickJS 适配层与 ASR / translation 业务路由。
- `b4e0e26`：manifest/models 投影、官方模型包、Codex / Claude Skill 与模板统一到 v5。
- `51029be`：namespace drain、资源释放、fixture / 签名测试、卸载保留配置与 UI 文案。

## Plugin API v5 契约

### manifest

- `apiVersion` 必须严格等于 `5`；v2/v3/v4/v6 均明确拒绝，不保留旧执行分支或 alias。
- `source.namespace` 必须等于插件 ID。运行时强制形成 SDK source `{ kind: "plugin", namespace }`，插件不能伪装 `builtin`。
- `capabilities` 是 SDK descriptor 的可移植子集：`moduleId`、`kind`、`providerIds`、`modelId`、`operations`、`features`、`tags`、`executionModes`。
- 当前开放 `speech-recognition` 与 `translation`；execution mode 只允许 `request-response`、`event-stream`、`realtime`，且 realtime 只允许语音识别。
- `models` 只保存 `id`、`label`、`providerId`、`capabilityId` 与默认项。`category`、`protocol`、`scenes`、`supports*` 不再由展示层重复声明；宿主从经 SDK 校验的 descriptor 投影应用模型目录。
- OCR / customization 仍是 Plugin API v5 的宿主扩展能力，但本任务不把它们伪装成 SDK ASR / translation descriptor；纯 OCR 插件允许 `capabilities/models` 为空。

### 唯一语义校验入口

Rust 只负责读取 manifest 和调用 QuickJS bundle；稳定 ID、descriptor、重复 module、重复 provider/kind/model 坐标都由 SDK `CapabilityClient.register/registerRealtime` 决定。独立 manifest validator 复用 9.12b 的 QuickJS compatibility bootstrap，并注入一个始终拒绝宿主调用的 scripted Host API，因此校验不会联网。

冲突错误会在 SDK 原始错误外补充正在注册的 module ID，能够同时看到待注册 module、占用 module 与双方 source namespace。插件加载失败时不会进入 registry。

## 运行时适配

- 文件 ASR：SDK module execute → 单一 adapter → `invoke({ operation: "transcribeFile", payload })`。
- translation：SDK module execute / event stream → 单一 adapter → `invoke({ operation: "translate", payload })`；`host.emit({type:"delta"})` 经 SDK `context.emit` 转发。
- 实时 ASR：SDK realtime session lifecycle → `realtimeStart` / `realtimeAudio` / `realtimeFinish` / `realtimeStop`；partial/final/finished/error 由 event router 归一。
- 适配器只存在于 `sdk-runtime/capability-entry.ts`，业务 `capabilities.rs` 和 `plugin_session.rs` 不再直接执行旧 ASR / translation 方法。
- 文件媒体仍使用 9.13b 提供的 `media.describe/readChunk`，保留 64 KiB 分块和 SDK 10 MiB 明确边界；没有开放路径、Node、全局 fetch 或 WebView SDK。
- secret config 字段从 `request.config` 移除。插件只能用 `await host.credentials.get(field)`，Rust 按 plugin namespace + provider + field 从 9.16 `CredentialStore` 注入；未声明字段拒绝。

## 卸载、停用与资源所有权

每个 `JsProviderRuntime` 以 `source.namespace` 注册 owner。停用或卸载前：

1. 对 namespace 下全部 Abort 标志置位；
2. 最多等待 5 秒让在途 QuickJS 退出；
3. runtime Drop 调用 SDK `unregisterSource(namespace)` / dispose，关闭 realtime session；
4. HostState 回收 HTTP stream、WebSocket、timer、trace span；
5. 未能释放则取消停用/卸载，不删除插件目录。

卸载会删除插件执行包、登录会话、Cookie / WebView 数据、插件数据与下载模型；provider profile 的非敏感配置改为禁用并保留，系统凭据继续按 9.16 产品语义保留。UI 确认文案已与此一致。

## 9.15 输入

1. 先确定 SDK 对外的 LLM 插件 module / descriptor 边界；现有 `CapabilityClient` 的 ASR / translation descriptor 不能作为 LLM 类型真相。若 SDK LLM runtime 仍是独立 registry，应复用同一 `source.namespace` 冲突、owner、Abort、timeout、logger/trace/credentials 规则，而不是复制一个插件专用执行核。
2. Plugin API 版本继续为 v5；新增 LLM 字段应是 v5 的向前扩展，不引入 v4/v5 双分支。
3. LLM 插件 source 固定 `{kind:"plugin", namespace:manifest.id}`，卸载复用 `drain_plugin_namespace` 并等待 streaming 任务释放。
4. 流式 token / reasoning / usage / finish / error 必须通过 SDK typed event 归一；插件只实现轻量 ABI，不打包 SDK。
5. secret 继续走 `host.credentials.get(field)`；插件 manifest 只声明 secret 元数据，WebView 和明文 profile 不得取得值。
6. 与内置 Groq / 其他 LLM provider 的 provider/model/module 坐标冲突必须由 SDK registry 拒绝并列出双方 source。
