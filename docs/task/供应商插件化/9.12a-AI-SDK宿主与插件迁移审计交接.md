# 9.12a · `@henjicc/ai-sdk` 宿主与插件迁移审计交接

> 性质：编码前审计与文件级实施方案，不含代码改动，不含真实网络调用。
>
> 审计基线：Say-It `0.4.0`；`@henjicc/ai-sdk` `0.1.8`；模型 SDK 抽离任务 9.5 已提交于 `2eb8a1685e17c9862f3fdcb9fbb3d04cd0a6f965`，交接为 `/Users/henji/Documents/VibeCode/Henji-AI/docs/task/模型SDK抽离/交接/9.5-SDK开放能力协议.md`。

## 1. 结论

Say-It 可以接入 `@henjicc/ai-sdk`，但不能把 SDK 放进 React WebView，也不能把 SDK 协议逻辑翻译一份到 Rust。目标形态应为：

1. **Rust 继续是唯一应用权威**：持有录音/DSP、会话、任务、文件、凭据、权限、日志、Tauri 命令和前端事件。
2. **SDK 在 Rust 持有的 QuickJS 中运行**：供应商协议、模型目录、HTTP/WS 请求构造、响应解析、轮询与错误归一化只保留 SDK 一份。
3. **内置供应商与 JavaScript 插件走同一种 SDK 契约**：ASR/翻译实现 capability module；LLM 使用 SDK 现有 `llm/streaming` 或其正式 provider adapter 扩展契约，不能把 Groq/LLM 伪装成 translation/capability module。两者只在信任域和加载来源上不同，不再保留“内置 Rust 分支”和“插件 invoke 分支”两套执行器。
4. **Apple Speech、Sherpa-ONNX、系统 OCR/本地 OCR 保持 Rust 本地链路**，只把其可发现描述投影进统一目录，不迁入 SDK。
5. **项目未发布，完成切换后直接删除旧实现**；只保留 `funasr → bailian`、明文密钥入系统凭据库、已安装插件清单版本三类一次性数据迁移，不保留长期 alias、双目录、双路由或 v3/v4 JavaScript 运行时兼容层。

目标调用关系：

```text
React UI
  └─ Tauri command / domain event
       └─ Rust application service（会话、DSP、任务、权限、投影）
            ├─ Apple / Sherpa / system OCR（原生链路，保持）
            └─ SdkRuntimeHost
                 └─ Rust-owned QuickJS context（按模型/任务惰性创建）
                      ├─ @henjicc/ai-sdk capability client
                      ├─ 内置 Bailian capability modules
                      ├─ SDK LLM/Groq executor
                      └─ 插件 capability / LLM adapter
                           └─ RuntimeContext
                                ├─ Rust HTTP / streaming HTTP
                                ├─ Rust WebSocket
                                ├─ system credential store
                                ├─ opaque media reader
                                └─ redacted logger / tracer
```

## 2. 已核实的现状

### 2.1 运行时边界

- `src-tauri/src/main.rs` 与 `src-tauri/src/state.rs` 持有正式运行状态；WebView 只消费命令与事件。
- `src-tauri/src/providers/plugin_runtime.rs` 已有 Rust-owned `rquickjs` 沙箱：64 MiB 内存、1 MiB 栈、相对模块加载、执行截止时间、取消标记、事件队列、HTTPS/WSS 白名单、重定向复核、资源/存储/加密/系统凭据会话桥。
- QuickJS 当前只有 UTF-8 `TextDecoder` 补丁，没有 `AbortController`、`Headers`、`Response`、`ReadableStream` 等 SDK `Transport` 所需对象；`host.http.request` 会一次性缓冲最多 16 MiB，不能承载 LLM SSE 的增量 `Response.body`。
- 因此，**“SDK 可在 ESM/CJS 使用”不等于“现有 QuickJS 可直接加载 SDK”**。正式编码前必须先完成 Web-compat 与流式宿主桥，并用 SDK 真实 bundle 验证。

### 2.2 在线 ASR 目录

`shared/asr-models.json` 当前共 10 条：1 条 Apple 本地模型和 9 条 `providerId = funasr` 的百炼在线模型。

| 协议族 | 模型 | 当前协议 | 场景/特性 |
|---|---|---|---|
| WebSocket 实时 · DashScope duplex | `fun-asr-realtime-2026-02-28`、`fun-asr-realtime` | `dashscope-duplex` | 听写/字幕；支持 vocabulary |
| WebSocket 实时 · Qwen realtime | `qwen3-asr-flash-realtime-2026-02-10`、`qwen3-asr-flash-realtime` | `qwen-realtime` | 听写/字幕 |
| HTTP 短音频 · Fun-ASR Flash | `fun-asr-flash-2026-06-15` | `file-sync-funasr-flash` | 文件听写/录音识别；context、时间戳 |
| HTTP 短音频 · Qwen | `qwen3-asr-flash`、`qwen3-asr-flash-2026-02-10` | `file-sync-qwen` | 只进文件听写，无时间戳 |
| HTTP 文件异步 | `fun-asr`、`qwen3-asr-flash-filetrans` | `file-async-oss` | 文件听写/录音识别；时间戳；`fun-asr` 支持 vocabulary |

模型 ID 不改；供应商 ID 从历史误名 `funasr` 一次性迁为 `bailian`。Fun-ASR 是模型族，不应继续作为供应商 ID。

### 2.3 翻译、LLM 与模型发现

- Qwen-MT 在 `src-tauri/src/providers/alibabacloud/translation.rs` 中直接发请求并解析 SSE；前端 `ui/src/features/translation/models.ts` 另有 3 条硬编码模型：`qwen-mt-flash`、`qwen-mt-plus`、`qwen-mt-lite`。
- 增量语义并不一致：flash/lite 是追加 delta，plus 是完整文本替换；这必须由 SDK adapter 的 typed event 固化，不能留在 UI 判断。
- Groq 和其他 LLM 现在由 Rust `genai` 执行；`src-tauri/src/application/smart_text.rs` 有 Groq Qwen3 思考参数特判，`src-tauri/src/application/llm_models.rs` 用 `genai` 拉远端模型。
- 当前设置页还提供 Groq、OpenAI、Anthropic、Gemini、DeepSeek、Volcengine、Kimi、BigModel、MiMo、Bailian、MiniMax、OpenRouter 与 custom。SDK 0.1.8 的可移植原生流式路径只覆盖 OpenAI-compatible Chat Completions；在 SDK 覆盖所有要保留的协议前，不能删除 `genai`。最终状态也不能两套并存：编码前必须决定“补齐 SDK 协议”或“删除未支持选项”。
- `src-tauri/src/application/catalog.rs` 和 `ui/src/features/asr/modelRegistry.ts` 暴露 `isQwen*`、`isFunasrFlash*` 等供应商专属布尔值；这会把协议路由泄漏到 UI，迁移时应换成 SDK descriptor 的通用 `kind`、`operations`、`features`、`executionModes`、`mediaTypes`、`tags`。
- `ui/src/features/asr/modelOptions.ts` 仍直接导入 `shared/asr-models.json` 取得同步默认值，形成第二个运行时消费入口；迁移后 store 初值用空/未就绪态，启动目录加载完成后统一 hydrate，不再保留共享 JSON。

### 2.4 配置、明文密钥与日志

- `ProviderProfile.config.apiKey` 会随 `say-it-state.json` 与 `.bak` 明文落盘；`get_provider_api_key` 还能把原文返回 WebView。
- `src-tauri/src/providers/plugin_secrets.rs` 已通过 `keyring` 使用 macOS Keychain / Windows Credential Manager，具备可复用的错误处理和大值分片方案，但目前只存网页登录会话。
- 插件清单的 `configFields.secret` 只会从前端响应剔除，保存时仍混在 profile config 中。
- `plugin_runtime.rs` 的日志只做关键字替换；`smart_text.rs` 的开发日志还会输出完整 prompt 与结果。SDK logger/tracer 只能接收 requestId、providerId、modelId、阶段、耗时、字节/字符数与归一化错误码，不得接收 API Key、Authorization、Cookie、音频内容、prompt 或模型正文。

### 2.5 插件 API

- 当前 JavaScript 插件：Plugin API 最新 v4、最低 v3；Host API 固定 v1；默认导出 `createProvider(host)`，再暴露 `invoke/realtime*` 等临时方法。
- v3/v4 清单只允许 `asr | translation | customization | ocr`，协议为 `plugin-realtime-v1`、`plugin-file-v1`、`plugin-translation-v1`、`plugin-ocr-v1`；没有 LLM 协议。
- manifest 的路径、签名、权限、allowedHosts、浏览器会话与本地网络校验属于宿主安全边界，必须留在 Rust；模型/能力语义校验应与 SDK descriptor 契约对齐。
- 插件执行目前另走 `commands/asr/plugin_session.rs` 和 `providers/capabilities.rs::Plugin`，与内置在线执行重复。

## 3. SDK 宿主适配接口

### 3.1 Rust 侧唯一入口

新增 `src-tauri/src/providers/sdk_runtime/`，对应用层只公开下列窄接口；应用层不感知 QuickJS、SDK provider pack 或插件方法名。capability 与 LLM 共用同一宿主基础设施，但保留各自正式协议：

```rust
pub struct CapabilityQuery {
    pub kind: String,
    pub provider_id: Option<String>,
    pub model_id: Option<String>,
    pub operations: Vec<String>,
    pub features: Vec<String>,
}

pub struct SdkExecutionOptions {
    pub request_id: String,
    pub timeout: Duration,
    pub cancel: CancellationToken,
    pub trust_scope: RuntimeTrustScope,
}

pub trait SdkRuntimeHost {
    fn descriptors(&self, query: &CapabilityQuery) -> Result<Vec<CapabilityDescriptorDto>, String>;
    async fn execute(
        &self,
        module_id: &str,
        input: serde_json::Value,
        options: SdkExecutionOptions,
        on_event: mpsc::Sender<serde_json::Value>,
    ) -> Result<serde_json::Value, String>;
    async fn open_realtime(
        &self,
        module_id: &str,
        input: serde_json::Value,
        options: SdkExecutionOptions,
        on_event: mpsc::Sender<serde_json::Value>,
    ) -> Result<SdkRealtimeSession, String>;
    async fn execute_llm(
        &self,
        request: serde_json::Value,
        options: SdkExecutionOptions,
        on_event: mpsc::Sender<serde_json::Value>,
    ) -> Result<serde_json::Value, String>;
    async fn discover_llm_models(
        &self,
        provider_id: &str,
        options: SdkExecutionOptions,
    ) -> Result<Vec<String>, String>;
    async fn cancel(&self, request_id: &str);
    async fn invalidate(&self, owner_id: &str);
}

pub struct SdkRealtimeSession {
    pub request_id: String,
    pub input: mpsc::UnboundedSender<SdkRealtimeInput>,
    pub completion: oneshot::Receiver<Result<serde_json::Value, String>>,
}

pub enum SdkRealtimeInput {
    Audio(Vec<u8>),
    Finish,
    Close,
}
```

实现要求：

- `request_id` 由 Rust 生成并贯穿 SDK、日志、前端事件；不能在 JS 侧另造业务任务 ID。
- Rust `CancellationToken` 同时触发 SDK `AbortSignal`、HTTP body、WS 与 QuickJS interrupt；超时与用户取消映射成不同错误码。
- 每个执行/实时会话创建独立或池化但隔离的 QuickJS context。插件 context 绑定自身权限与 providerId；内置 context 绑定预置 provider scope。不能把一个无作用域的 RuntimeContext 给所有插件共享。
- descriptor 查询只加载轻量 discovery bundle；执行时才加载所选 module bundle。插件启用/更新/卸载时 `invalidate(owner_id)` 先取消活跃请求，再 dispose/unregister，最后刷新目录 revision。

### 3.2 QuickJS bridge

新增仓库根 `sdk-runtime/` 作为**非 UI 的宿主集成 TypeScript**：

| 新文件 | 责任 |
|---|---|
| `sdk-runtime/host-adapter.ts` | 把受控 `__sayitHostCall` 适配为 SDK `RuntimeContext` |
| `sdk-runtime/web-compat.ts` | SDK 实际 import graph 所需的最小 `AbortController/Signal`、`Headers`、`Response`、`ReadableStream` 兼容层 |
| `sdk-runtime/catalog-entry.ts` | 只导入 descriptor/discovery，输出 JSON DTO，不导入执行 pack |
| `sdk-runtime/bailian-speech-entry.ts` | 惰性注册百炼 9 个 ASR 与 vocabulary management modules |
| `sdk-runtime/bailian-translation-entry.ts` | 惰性注册 Qwen-MT modules |
| `sdk-runtime/llm-entry.ts` | 封装 SDK `llm/streaming`、Groq/retained provider adapter 与模型发现；不注册为通用 capability |
| `sdk-runtime/plugin-entry.ts` | 加载插件 v5 module、注册、执行与 session lifecycle |
| `scripts/build-ai-sdk-runtime.mjs` | 用显式 esbuild 依赖生成分入口、tree-shaken 的单文件 ESM bundle |
| `tsconfig.sdk-runtime.json` | 对宿主集成代码独立 strict typecheck；不能被 `ui/src` 的宽松配置掩盖 |

`src-tauri/build.rs` 在 Cargo/Tauri 构建时调用 bundle 脚本，把产物写入 `OUT_DIR`；Rust 用 `include_bytes!/include_str!` 嵌入。不要提交生成 bundle，也不要从 WebView 或运行时 `node_modules` 解析包。

当前 `Transport.fetch(): Promise<Response>` 的精确兼容要求：

- `http.request`：普通 JSON/短响应；保留 HTTPS、redirect revalidation、响应体上限与取消。
- 新增 `http.stream.open/read/close` 内部操作：用于 SSE/流式 body；每个 chunk 有总量/单块上限与背压，Drop/Abort 必须关闭 reqwest stream。
- JS `Response.body.getReader()` 由 bridge 映射上述流；不能先缓冲整个 SSE 再伪装流式。
- `RealtimeTransport.connect()` 映射现有 Rust WSS 桥，JS 侧形成 `AsyncIterable<RealtimeMessage>`；close、错误、Abort 只结束一次。
- `MediaReader.read(ref)` 只接收 Rust 注册的不透明 media ref 或显式 bytes。插件不得把任意文件路径传给 SDK；Rust 在创建任务时把选择文件注册为句柄。
- `CredentialStore.get(scope, providerId)` 由 Rust 校验当前 context 的 owner/provider/capability 后读系统凭据库；插件不能读取其他 provider 的 secret。
- `Logger/Tracer` 走一个结构化、脱敏的宿主操作；不得让插件自报的字段覆盖真实 requestId/providerId/moduleId。

Host API v1 可以保留：上述流式 HTTP、credential、media 与 trace 是**向 v1 增加受控原语**，没有改变既有方法语义。若实现中不得不改现有 `http.request`/WS 的返回语义，再把 Host API 整体升 v2；不能名为 v1 却做破坏性变更。

### 3.3 媒体编码边界

SDK 9.5 的批量 ASR 输入拟采用显式 bytes 或宿主 media ref；这与 Say-It 边界一致，但尚未解决供应商期待的编码：

- `fun-asr-flash` 当前需要 Opus/Data URI；
- Qwen 短音频当前使用 MP3；
- 文件异步当前需要预签名上传与 OSS multipart；
- Sherpa 本地继续消费解码后的 mono 16 kHz PCM。

迁移时保持 `audio_prep` 与编码器为 Rust 宿主媒体变换服务，向 SDK 交付标明 mime/filename 的 bytes/media ref。供应商选 Opus/MP3/OSS 的决定属于 SDK Bailian module；Rust 不能按 modelId 分支。若 SDK module 只接收某种 mime，它必须在 descriptor/input validation 中显式声明，Rust 按通用 media requirement 调用转换器。

## 4. 插件适配策略

### 4.1 版本策略

- 新的 JavaScript 插件统一为 **Plugin API v5**，`PLUGIN_API_VERSION = PLUGIN_MIN_API_VERSION = 5`。
- 删除 v3/v4 JavaScript 运行时兼容分支与测试，不提供 `createProvider(host) → module` 的长期翻译层。项目未发布，插件应由新版 Skill 重新生成。
- Host API 继续为 v1，前提是只做兼容性新增；详见 3.2。
- 本地模型包虽不执行 JS，也统一把 manifest `apiVersion` 改为 5。对已安装 v4 model-pack 只做一次性清单字段迁移并原子改写，之后注册表只接受 v5；不在每次加载时保留 v4 分支。

### 4.2 v5 入口与 LLM 协议

JavaScript 插件入口改为 SDK module/adapter factory：

```ts
export default function createPluginModules(): {
  capabilities?: readonly AnyCapabilityModule[]
  llmAdapters?: readonly LlmPluginAdapterV1[]
}
```

插件不再直接接收 `host`；capability 执行时的网络、凭据、媒体、日志和取消只从 SDK `CapabilityExecutionContext.runtime` 获得。LLM adapter 必须接收同一份已作用域化 RuntimeContext 与 AbortSignal，复用 SDK LLM DTO、SSE parser、错误归一化和事件类型。宿主为每个插件 context 注入已作用域化的 RuntimeContext。

清单不再用 app-specific `category + protocol + scenes` 作为能力真相，改为声明 SDK descriptor 的稳定子集：`moduleId/kind/providerIds/modelId/operations/features/tags/executionModes`。应用场景（听写、字幕、文件转写、智能问答）由 Rust 对 descriptor 做投影，不反塞进 SDK。

LLM 插件使用独立协议版本 **`plugin-llm-v1`**；它表示插件 module 的 LLM 输入/事件/输出契约，不等于 Plugin API 版本。未来只改 LLM 数据协议时升 `plugin-llm-v2`，不连带提升整个包格式；只有 manifest/加载生命周期破坏性变化才升 Plugin API。

LLM v1 至少锁定：system/user/assistant history、纯文本增量 token、reasoning delta、finish reason、usage、Abort、timeout、provider/model trace metadata。它优先复用 SDK `LlmChatRequestDto`、`LlmStreamEvent` 与 outcome；若 SDK 还没有可供第三方实现的 public adapter interface，必须先在 SDK 新增并发布，Say-It 不自造第二份近似类型。工具调用、图片、联网搜索只有 SDK 契约真正支持并通过测试后才能在 descriptor features 中声明；不得靠插件任意 JSON 冒充。

### 4.3 校验与冲突处理

- Rust 继续校验包结构、路径穿越、符号链接、哈希/签名、权限、browser session、Cookie 范围与 allowedHosts。
- descriptor 语义使用 SDK bundle 中的 validator 校验；Rust 只投影验证结果，避免复制一份枚举真相。
- 保留并强化 ID 冲突：`bailian`、`groq`、`apple-speech`、系统 OCR 和本地引擎 ID 为 reserved；插件 provider/model/module ID 不能与内置或已安装项冲突。
- module ID 使用稳定、全局唯一形式，例如 `providerId:modelId:operation`。SDK client 的重复注册错误必须向安装器返回，不能后加载覆盖先加载。
- 插件 enable/reload/update/uninstall 顺序固定为：阻止新任务 → cancel 活跃任务 → dispose context/module → 原子替换包 → 重建 descriptor cache → 推进 catalog revision。

## 5. 一次性数据迁移

### 5.1 `funasr → bailian`

把 `CURRENT_STATE_SCHEMA_VERSION` 从 2 升为新的明确版本，迁移只运行一次：

1. `profiles[].id == "funasr"` 改为 `"bailian"`；`kind == "alibabacloud-funasr"` 改为 `"sdk:bailian"`。
2. `defaults.asr/translation == "funasr"` 改为 `"bailian"`。
3. 历史 `defaults.llm == "funasr"` 按当前产品既有迁移意图改为 `"llm-groq"`，不要把 Qwen-MT capability 误当通用 LLM 默认项。
4. vocabulary map 的 key 是模型 ID，9 个模型 ID 不变，因此原样保留。
5. 持久化的 ASR/字幕/文件转写模型选择只存 modelId，无需改名；目录刷新后自然解析到 provider `bailian`。
6. 插件注册前先保留 `bailian`，若已有未发布测试插件占用该 ID，迁移应明确报冲突并要求卸载/改包，不做隐式重命名。
7. 迁移成功写回后删除运行时 `FUNASR_PROVIDER_ID`、旧 kind、旧前缀 fallback 与 alias 测试。

### 5.2 密钥迁系统凭据库

新增通用 `src-tauri/src/providers/credential_store.rs`，复用 `keyring` 低层错误处理；网页登录大 session 可继续使用现有分片格式，但 API Key 使用简单单值记录：

```text
service: com.henjicc.sayit.credentials
account: provider:{providerId}:{fieldKey}
```

迁移算法必须可失败、幂等且不丢密钥：

1. 从主文件与可用备份中加载状态，扫描 `apiKey` 和 `configFields.secret == true` 的字段。
2. 逐项写 keyring，再立即回读比对；任一失败则删除本轮已新写项（尽力而为）、不提升 schema、不改原状态文件，并在设置页呈现阻塞错误。
3. 全部凭据确认后，构造剔除 secret 的新 JSON；使用同目录临时文件、flush/sync 与原子替换提交。
4. 迁移不能调用现有“先把旧主文件复制成 `.bak`”的路径，否则备份会永久保留明文。成功后把主文件和 `.bak` 都写成无 secret 状态；失败时原文件仍在。
5. 最后提升 schema。后续保存逻辑对任何 secret 字段都拒绝序列化，防止回归。
6. 删除 `get_provider_api_key`。设置页默认只拿 `hasSecret`；如保留“显示”按钮，单独的显式 reveal 命令只在用户动作时读 keyring，返回值不得进入 store/snapshot/log。

8. SDK CredentialStore 在 Rust 内直接读 keyring；QuickJS 初始化 payload 不再包含 `apiKey`。

## 7. 按需注册与模型发现

1. 启动时只执行 `catalog-entry`，取得 SDK descriptor；不 import Bailian/Groq provider implementation。
2. Rust 将 SDK online descriptors、Apple/Sherpa local descriptors、启用插件 manifest descriptors 合并、查重、排序并缓存，生成一个 catalog revision。
3. UI 只按 `kind/operations/features/tags/executionModes` 筛场景；默认模型是应用设置，不是 SDK 全局 default。首次安装可由产品 migration 选择一次，但 SDK 不声明“默认供应商”。
4. 发起任务时用 `providerId + modelId + operation` 精确解析 moduleId；只加载对应 bundle/context 并 register。
5. 内置和插件的 ASR/翻译 module 都用同一 capability client；内置和插件 LLM 都走 SDK LLM executor/provider adapter。Rust 只根据 trust scope 选择不同 RuntimeContext 权限，不根据 providerId 写执行分支。
6. Apple/Sherpa 不注册进 SDK executor，但它们以同构 descriptor 出现在 catalog composer 中；应用路由只区分 `executionOwner = native | sdk`，不区分具体在线供应商。
7. 不新增 SDK JSON catalog 快照。Rust 是非 TS 消费方，但已经能在 QuickJS 执行轻量 ESM 查询；落一份构建期 JSON 会制造第二真相。只有 QuickJS discovery 的启动/包体指标不达标并有实测证据时，才重新评估由 SDK 官方 build 产出的、带版本/hash 校验的生成 artifact。

## 9. 关键验收断言

- 全仓在线协议实现只有 SDK bundle 一份；Rust 没有 `if model == ...`、Qwen/FunASR/Groq 协议分支。
- React/WebView 不加载 `@henjicc/ai-sdk`、不持有原始 PCM/ASR 流、不执行供应商网络请求。
- 9 个在线 ASR modelId 与现有场景/时间戳/vocabulary/context 事实不丢；providerId 全部为 `bailian`。
- Qwen-MT 模型目录来自 SDK；UI 不硬编码模型或增量策略。
- Groq 的执行、流式、reasoning、模型发现与取消不再经过 `genai`。
- Apple/Sherpa 本地结果、取消、DSP 和前端事件契约不变。
- API Key/secret 不出现在 `say-it-state.json`、`.bak`、前端 snapshot/store、QuickJS initialize payload 或日志。
- Plugin API v5 是唯一 JavaScript 执行协议；Host API v1 保持兼容；LLM 协议独立版本化。
- capability module 按需加载；目录查询不产生网络请求、不读取凭据、不注册所有 provider。
- 所有替换点有 fixture/loopback 证据后才删除旧文件；最终不存在长期双实现。

## 10. 9.12 正式编码前置条件

以下条件未全部满足前，不应开始大规模删除或切路由：

1. `@henjicc/ai-sdk` 发布一个 Say-It 可安装的非 workspace 版本，并在 SDK 自己的依赖声明中包含所有运行依赖；Say-It lockfile 固定精确版本。
2. SDK 9.5 的 `CapabilityClient`、speech-recognition、translation、realtime、descriptor discovery 契约定版；当前可用方向为 `execute/onEvent/Abort/timeout` 和 `openSession/send/finish/close/cancel`。
3. SDK 提供真正可执行的 Bailian modules：本文 9 个 ASR、3 个 Qwen-MT、vocabulary management；只提供 descriptor/fixture module 不足以切换。9.5 明确把这些留给后续 9.6/9.7。
4. SDK 明确每个 ASR module 的媒体 mime/编码、短音频大小/时长、OSS multipart、轮询与取消语义；Say-It Rust 媒体变换与其对齐。
5. SDK 增加 Groq preset/model/protocol fixture，并决定 Say-It 当前 Anthropic/Gemini/Responses/OpenRouter/custom 等选项的去留。Groq 应走 SDK 现有 `@henjicc/ai-sdk/llm` / `llm/streaming`，不能伪装为 capability module。若允许第三方 LLM 插件，SDK 还需发布稳定的 adapter 扩展接口。最终不得为未覆盖协议保留 `genai` 旁路。

8. 确认 SDK 错误码、事件与 provider metadata 不含 secret；Say-It 再锁定 DTO mapping。
9. 编码顺序严格按第 8 节推进，先桥与迁移、后业务切换、最后删除；不能先删除旧实现再补宿主能力。
