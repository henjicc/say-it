# 9.19b 运行时边界修复交接

> 10.1 后凭据读取仍保留有界 worker 与宿主 deadline，但后端已改为应用本地加密 vault，不再调用 Keychain/Credential Manager；下文的供应商 live 系统凭据状态仅为历史边界。

## 结论

9.19a 交叉审查发现的五项问题均已按根因修复，并补充了无需真实供应商、不会付费的断牙测试：

1. 百炼 SDK 与插件实时 ASR 在省略 DSP 参数时统一使用 `DspParams::default()`，不再静默丢弃所有 PCM。
2. Qwen-MT 的取消信号从字幕会话和助手 generation 一路传入 `TranslationProvider`、宿主 `AtomicBool` 与 QuickJS RuntimeContext；取消后等待工作线程收尾，HTTP stream 等资源归零。
3. Plugin v5 capability 事件改为串行异步队列；execute、finish、close、unregister、dispose 都在相应边界 drain。`realtimeFinish()` 的非空确认值只视作 ack，不再抢先覆盖由 final/finished 事件组成的 transcript。
4. QuickJS HTTP 手工重定向只处理 301/302/303/307/308；304 作为普通响应返回。301/302 POST 与 303 非 GET/HEAD 按 Fetch 语义改为 GET 并移除 body 头，307/308 保持原请求；跨 origin 移除凭据头，每一跳仍重新校验协议、权限和 `allowedHosts`。
5. RuntimeContext logger 在结构化记录中保留经过脱敏、限长的稳定 `message` 字段，不再只留下 metadata。

## 关键实现边界

- 实时音频仍只在 Rust `StreamDsp` 中完成采样率转换与 PCM16 编码；SDK 和插件连接器只接收字节。
- 字幕的 `CancellationToken` 归属于单次 Subtitle Session。停止或启动失败会取消该会话已派发的全部翻译，不影响下一次新会话。
- 助手专用翻译复用 `AssistantRuntime::generation`；`assistant_cancel` 会先取消 generation，再停止听写会话。
- 翻译取消不是只丢弃迟到结果：宿主取消标志会使阻塞 HTTP 读退出，调用方等待 QuickJS 工作线程和资源释放完成后才返回取消错误。
- Plugin v5 事件入口仍保持同步 `host.emit` 兼容性，异步顺序由适配层内部 Promise 队列保证；清理逻辑放在 `finally`，事件回调失败也不能跳过 stop/unregister/dispose。
- HTTP 跳转继续由 Rust 宿主执行，不开放全局 Fetch，也没有放宽网络白名单。

## 断牙测试

- `omitted_dsp_params_still_produce_realtime_pcm`：省略参数仍产生 PCM，锁住模型对比与外部调用的合法缺省输入。
- `pre_cancelled_translation_stops_before_credentials_or_network`：预取消在读取凭据、创建网络请求前终止。
- `cancelling_translation_aborts_http_stream_and_releases_resources`：本地脚本化 Qwen-MT HTTP 流在执行中取消，结果为取消且 HTTP/WS/span/timer 资源为 `(0,0,0)`。
- `plugin_v5_adapter_executes_translation_file_asr_and_realtime_asr`：连接器在 emit final/finished 后返回非空 ack，最终仍得到事件 transcript。
- `fetch_redirect_*`：穷举 304、301/302/303、307/308、跨 origin 凭据剥离和跳转白名单拒绝。
- `quickjs_fetch_applies_redirect_method_body_and_cross_origin_header_rules`：通过两个本地端口验证 QuickJS→Rust 宿主的 302/307 实际请求方法、body 与头部。
- `injects_scoped_credentials_media_logging_and_trace_without_leaks`：稳定消息保留，包含敏感内容的消息和 metadata 均脱敏。
