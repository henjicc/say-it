# 9.15b LLM 插件统一接入交接

## 结论

Say-It 已精确锁定 `@henjicc/ai-sdk@0.2.2`，Plugin API v5 正式开放 `kind=llm`。插件仍只实现轻量 `invoke` ABI，不打包 SDK；QuickJS 宿主把它包装为正式 `LlmModule`，注册、执行、发现、冲突、取消、drain、unregister 与 dispose 全部使用 0.2.2 的 `LlmModuleClient`。

SDK source 的实际结构为 `{kind:"plugin", namespace:<pluginId>}`，其完整身份写作 `plugin:<pluginId>`。清单只能声明 `source.namespace=<pluginId>`，不能伪造 source kind。

## Manifest v5 契约

LLM 沿用唯一的 `capabilities[]`，不新增临时顶层协议：

```json
{
  "moduleId": "example.llm.chat",
  "kind": "llm",
  "providerIds": ["example"],
  "modelId": "chat",
  "operations": ["chat", "discover-models"],
  "features": ["reasoning", "usage", "sampling"],
  "tags": [],
  "executionModes": ["request-response", "event-stream"],
  "acceptedInputKinds": ["text", "image"],
  "modelDiscovery": true,
  "contextWindow": 32768,
  "maxOutputTokens": 4096
}
```

宿主/SDK共同强制：

- `acceptedInputKinds` 至少含 `text`，只允许 `text/image/audio/video`；当前 Say-It 会话只发送文本，多模态只是可扩展筛选契约。
- LLM 只允许 `request-response/event-stream`；streaming、reasoning、usage、tool、JSON/schema 等从 features 派生后再由 SDK descriptor validator 校验。
- `moduleId` 必须以插件 namespace 开头；唯一 provider 必须等于 `manifest.provider.id`；每个静态 model 必须引用同坐标 module。
- 同 module ID 或 provider/model 坐标冲突由 `LlmModuleClient` 拒绝。已覆盖插件占用内置 Groq 及插件间重复坐标，错误包含待注册与既有 module/source。
- 模型发现只允许返回清单中已有静态 module 的 modelId；未声明结果明确拒绝，不制造“下拉可选但无法执行”的假模型。

最小无密钥 fixture：`src-tauri/tests/fixtures/plugin-llm-v5/`。

## 插件调用协议

- 聊天：`invoke({operation:"chat", payload})`；payload 含 provider/model、messages、requestId、mode 与可选 reasoning/capabilities/policy。
- 增量正文：`host.emit({type:"text",text})`。
- 增量推理：`host.emit({type:"reasoning",text})`。
- 用量/结束/失败：`usage` / `finish` / `error`；adapter 收集终态，SDK 统一发射 `Usage → Finish → Done` 或 `Error`。
- 最终返回：`{output,reasoningOutput,usage,finishReason}`。
- 发现：`invoke({operation:"discoverModels",payload})`，返回 `[{modelId,displayName,contextWindow,maxOutputTokens}]`。
- Rust 外部取消以 `AtomicBool` 中断 QuickJS 并关闭宿主 HTTP/WS/timer/trace；SDK timeout/cancel 信号同时存在。LLM client 的 drain/unregister/dispose 在 Drop 中顺序执行。

## Say-It 接入

- `smart_text`：内置 Groq、插件 LLM、既有 genai 三路清晰分发；插件流式/非流式共用同一 SDK module adapter，保留 system/user/history/reasoning/structured-json 请求结构。
- `llm_models`：插件静态模型进入 profile；可选 discovery 只刷新静态模型可用性，不动态创建 module。
- provider/model 选择：Home、智能优化、语音助手、LLM 设置均改为按 `capabilities.includes("llm")` 判断。
- LLM 设置：插件显示静态模型与 manifest secret，隐藏手动添加、直接删除；停用/卸载仍由插件管理执行，凭据继续走 CredentialStore。
- 插件不存在时不会生成任何插件 LLM profile 或空模型入口。

## 未做与边界

- 未发起任何真实 LLM/付费请求；网络协议只由 scripted/loopback 与既有 bundle tests 验证。
- 没有动态为发现结果生成新 module；0.2.2 module 坐标是静态稳定契约，9.17 若要开放真正动态模型，必须先在 SDK 定义原子“发现并注册”协议，不能只把名字塞进 UI。
- 插件 `host.emit` 是同步入队，SDK adapter 会串行 await 下游 typed events，但不承诺把背压反向传到上游供应商连接；高频连接器仍需按官方协议节流。
- Rust 强制取消会中断 QuickJS并回收宿主资源；不会继续等待已失去宿主的插件 Promise。

## 9.17 输入

1. 以 `capabilities[].kind=llm` 和本交接事件协议作为唯一插件 LLM ABI，不新增 v3/v4/临时 llm 分支。
2. 插件 source 坐标按 `{kind:"plugin",namespace:<pluginId>}`；停用/更新/卸载先 drain namespace，再 unregister/dispose，凭据保留。
3. 若 9.17 做完整安装/升级 E2E，使用 `src-tauri/tests/fixtures/plugin-llm-v5`，覆盖安装、设默认、流式问答、停用、卸载、资源归零与配置保留。
4. 若要动态模型发现，先扩 SDK module registry 原子协议；当前只允许发现静态 module。
5. 真实供应商验收仍需用户明确授权密钥与付费网络，本任务没有建立该授权。
