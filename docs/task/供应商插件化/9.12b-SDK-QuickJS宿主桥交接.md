# 9.12b · SDK QuickJS 宿主基础桥交接

> 性质：宿主基础设施实现，不含百炼、Qwen-MT、Groq 业务路由，不含真实网络、麦克风或付费调用。
>
> 上游：`9.12a-AI-SDK宿主与插件迁移审计交接.md`、Henji-AI 9.5～9.10 SDK 交接；实现基线为 Say-It `0.4.0`。

## 1. 结论与边界

已在 Rust 管理的 QuickJS 沙箱中建立 SDK `RuntimeContext` 所需的宿主基础桥。网络、WebSocket、文件、凭据、日志、追踪、取消和超时仍由 Rust 掌权；QuickJS 只运行 SDK/供应商协议代码；React WebView 没有加载 SDK，也没有获得新的文件、网络或凭据能力。

本任务没有把百炼/Groq 路由接到新桥，也没有新增第二套业务执行器。当前旧插件执行仍是唯一线上路径，新桥只是同一个 `plugin_runtime` Host API 上的受控基础能力。9.13 接入正式 SDK bundle 时必须直接切换并删除旧在线供应商分支，不能长期并行。

Say-It 当前尚未安装/发布可消费的 `@henjicc/ai-sdk` 新版本。因此本次只实现结构适配，不复制 SDK 的 TypeScript 类型真相；`create_with_sdk_bindings` 是后续正式入口，尚无生产调用方。

## 3. Rust Host API 与生命周期

| 原语 | 语义与限制 |
|---|---|
| `http.stream.open/read/close` | 复用既有 HTTPS/回环权限、allowedHosts 与重定向逐跳复核；返回状态/头/最终 URL，单次最多返回 64 KiB，单流最多 64 MiB；读阻塞受 Rust cancel/deadline 打断。 |
| `websocket.open/send/close` | 复用 WSS/回环准入；保留自定义请求头和 subprotocol；支持 text/bytes、close code/reason；错误、远端关闭、Abort、deadline 都收口为一次结束并清理连接。 |
| `timer.open/close` | 为 SDK 的 `setTimeout/clearTimeout` 提供宿主事件；上限 30 分钟；Drop、取消或失败清理未触发计时器。 |
| `media.read` | 只接受 Rust 为本次任务注册的 opaque ref；绝对路径或其他任务句柄都无法读取；不开放 QuickJS 文件系统。当前单文件硬上限 256 MiB。 |
| `credential.get` | `SdkHostBindings` 同时校验 `providerId` 与 scope；没有绑定、跨供应商、跨 scope 均拒绝。 |
| `runtime.log` | request/provider/owner 以 Rust 绑定为准；插件 message 不落记录，只保留白名单标量 metadata，防止 Authorization、Cookie、prompt/正文泄漏。 |
| `runtime.trace.start/end` | span ID 由 Rust 生成；重复 end 拒绝；只记录宿主身份、白名单属性、耗时和失败布尔值。 |

任一 JS 调用异常、取消或超时都会在 Rust 侧强制释放 HTTP stream、WS、timer 与未结束 span；`HostState::drop` 再做兜底。外部取消标记和 Rust deadline 是阻塞 I/O 的权威中断条件；9.13 必须把 SDK `timeoutMs` 同步传给 `JsProviderRuntime::call`，不能只依赖 JS timer，因为 QuickJS 在同步 Host call 阻塞期间无法调度 JS callback。

## 4. QuickJS RuntimeContext

`globalThis.__sayitCreateRuntimeContext()` 当前返回与 SDK 9.5 公共契约结构一致的对象：

- `transport.fetch`：把标准 URL/RequestInit 映射成流式 HTTP，并返回增量 `Response.body.getReader()`；支持 string、ArrayBuffer、TypedArray 和本任务最小 FormData/Blob multipart。
- `realtime.connect`：返回 `messages: AsyncIterable`、`send`、`close`，消息只为 string/Uint8Array。
- `media.read`：opaque ref → Uint8Array/mimeType/filename。
- `credentials.get`：scope/provider 双重受限。
- `logger`、`tracer`：只进入 Rust 的脱敏结构化出口。

兼容层只覆盖 SDK 当前 import graph 实际所需的最小语义，不冒充完整浏览器：

- 明确没有全局 `fetch`、Node `process/require`、文件系统和 WebView bridge。
- `URL` 覆盖绝对 URL、简单相对 URL、`protocol/hostname/pathname/origin/toString`；不是完整 WHATWG URL 实现。
- `Blob/FormData` 覆盖 SDK 百炼 OSS multipart 当前用法；没有完整浏览器表单 API。
- `Response/ReadableStream` 覆盖 SDK 当前文本、JSON、arrayBuffer、reader/cancel 用法；没有完整浏览器 clone/tee 等语义。
- `setTimeout/clearTimeout` 由 Rust 事件驱动；不接受字符串求值。

## 5. 权限与脱敏证据

- 无 `network/localNetwork` 的 context 即使直接调用 adapter，也在 Rust 准入前被拒绝；adapter 不能绕过 manifest capability。
- HTTP 重定向和 WS URL 都复用 `parse_allowed_url`；回环明文仅限显式 `localNetwork`，外网仍要求 HTTPS/WSS 与 allowedHosts。
- 媒体测试证明 `/etc/passwd` 这类任意路径不能作为 ref；只识别当前任务的 UUID/opaque handle map。
- 凭据测试证明 `bailian/api-key` 能读取，而 `groq/api-key`、`bailian/other` 被拒绝。
- 日志/trace 测试主动传入 `sk-sayit-test-secret`、`authorization` 和嵌套 token，最终 recorder JSON 不含这些内容。
- SDK bridge 只被 `include_str!` 嵌入 Rust QuickJS；UI 目录与 Tauri command 清单均未改动。

## 7. 已知限制与未做项

- **没有安装或打包真实 `@henjicc/ai-sdk`**：当前构建脚本只编译 bridge。真实 SDK bundle、轻量 catalog entry、百炼/Qwen-MT/Groq 按需 entry 属于 9.13。
- **没有具体系统凭据 reader/正式日志 recorder**：本任务锁定 trait 和作用域校验；9.13 应复用现有 keyring 基础设施实现，不把 `ProviderProfile.config.apiKey` 再传入 JS initialize payload。
- **没有真实网络、麦克风、Keychain 写入或付费验证**。
- **大媒体仍有内存风险**：`media.read` 当前经 JSON 字节数组进入 64 MiB QuickJS；Rust 的 256 MiB文件上限高于 QuickJS 实际可承载量。9.13 在启用文件 ASR 前必须把媒体桥改为 chunk/base64/宿主缓冲方案并对官方最大输入做内存压测，或明确收紧输入上限；不能假装 256 MiB 可用。
- 最小 URL/FormData/Response 只保证已审计 SDK 用法。安装真实 bundle 后必须跑 import-graph smoke；缺少 Web API 时扩充这一唯一兼容层，禁止在每个 provider entry 各写一份 polyfill。
- 旧 Plugin API v3/v4 与 `createProvider(host)` 尚未删除，因为本任务没有接业务路由；9.13 切换时按 9.12a 直接升 v5 并删除旧执行契约，不做双执行兼容。
