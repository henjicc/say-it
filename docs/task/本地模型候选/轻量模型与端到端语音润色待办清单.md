# 轻量本地模型与端到端语音润色待办清单

记录后续围绕「低显存本地听写润色（目标 ≤ 2.0 GB）」与「开源 ASR-LLM 合体改造」的分阶段路线、触发条件、止损红线与防坑注意事项。

## 阶段 A：2B 级纯文本听写润色多实验与优选（进行中）

**目标**：在不显著牺牲听写润色质量的前提下，验证能否把本地整理模型显存从 4B（~3.4 GB）压到 1.5～2.0 GB，并为后续是否合并到 `Qwen3-ASR-1.7B`（同源 Qwen3-1.7B 解码器）提供直接基线。

- [ ] **实验一**：`Qwen3.5-2B`（全参 bf16，`lr=2e-5`，3.5 ep）全量关键 checkpoint 评测
- [ ] **实验二**：`Qwen3.5-2B`（全参 bf16，`lr=1e-5`，2.5 ep，每 100 步保存不设上限）训练与全 checkpoint 评测
- [ ] **实验三（双卡并行）**：`Qwen3-1.7B`（纯 Transformer，无混合循环层快照显存开销，`lr=2e-5`，2.5 ep，每 100 步保存）训练与全 checkpoint 评测
- [ ] **SFT 三轮盲评裁判**：确定性规则检查 + 6 项原子缺陷布尔判定 + 多模型三轮洗牌多数表决（不展示参考答案、混入匿名 4B 锚点防漂移）
- [ ] **阶段二 DPO 精调 + 终极裁判**：在 SFT 冠军上用交叉验证偏好对做低学习率 DPO，再跑三轮盲评决出最终胜者并自动释放云端 GPU
- [ ] **本地交付验收**：
  - [ ] 导出最终 GGUF（`Q4_K_M` / `Q5_K_M` / `Q6_K`），注意 Qwen3.5 需清理 MTP 元数据，Qwen3-1.7B 为标准纯 Transformer GGUF
  - [ ] 本机实测真实显存占用、加载耗时、长短句延迟（Windows Vulkan / macOS Metal）
  - [ ] 人工盲测 `top2_human_check.md`（约 20～30 条高分歧真实样本），决定是否发布轻量文本包

## 阶段 B：零合成音频「单显存二合一」验证（优先于音频微调）

**核心思路**：彻底不动原版 `Qwen3-ASR-1.7B` 的听写权重，只给它的 1.7B 解码器单独训一个几十 MB 的**纯文本润色 LoRA 插件**。推理时在 `llama.cpp` 里常驻一份 `Qwen3-ASR-1.7B`（~1.8 GB）：
1. 听写阶段**卸载 LoRA** → 100% 原版识别精度，零声学退化；
2. 润色阶段**毫秒级挂载 LoRA** → 复用显存里同一份 1.7B 解码器跑文字润色，总显存压在 ~2.0 GB。

### 触发条件
- 阶段 A 的实验三（原始 `Qwen3-1.7B`）盲评成绩达到日常可用水平（尤其是轻档与中档），值得把双模型显存从 5.2 GB 压到 ~2.0 GB。

### 待办项
- [ ] 用与阶段 A 完全一致的纯文本训练集，给 `Qwen3-ASR-1.7B` 内部的解码器单独训一个 LoRA（`r=32~64`）
- [ ] 对比「`Qwen3-ASR-1.7B` 解码器 + 纯文本 LoRA」与「原始 `Qwen3-1.7B`」的盲评差距，确认阿里 ASR 专化训练是否削弱了它的文字改写悟性
- [ ] 如差距可接受（例如在 2～3 个百分点内），优先推进 `sayit-llm` 开启 `llama-cpp-sys-2` 的 `mtmd` 特性与 LoRA 动态热插拔

## 阶段 C：真·端到端「原生上下文 + 语音直出润色」（基于公开真人语音库）

**核心思路**：放弃“全靠 AI 配音合成音频”的高失真方案，改走**「云端免费 CPU 流式筛选公开真人语音 → 大模型反向生成润色目标与屏幕上下文 → 冻结编码器 LoRA 微调」**，90% 以上声学数据来自真实人类与真实麦克风，仅用少量自录真实听写补齐代码/办公高频中英混说场景。

### 触发条件
- 阶段 A/B 完成后，明确希望进一步拿掉「先转字、再改字」的串行延迟，并获取**声学纠错红利**（听声音 + 看屏幕直接纠正同音错字和专有名词）。

### Stage 0：0 训练基线摸底（约 0.5 天，0 训练算力）
- [ ] **原版 `Qwen3-ASR-1.7B` 长上下文压测**：用现有真实录音集，把 1200 字 `<screen>` + 48 条 `<hotwords>` 注入 `prompt`，实测是否引起识别率下降、屏幕抄写或延迟飙升
- [ ] **备选底座对照（可选）**：用 `llama-mtmd-cli` 快速抽测 20 条中文/中英混说听写跑 `Gemma 4 E2B`（Q4_K_M），核对真实显存、速度与中文 CER（若显存 > 3.2 GB 或中文 CER 落后 > 2pt 直接放弃，锁定 `Qwen3-ASR-1.7B`）

### Stage 1：云端零本地搬运造数据 + 最小闭环 PoC（约 4,500～6,000 条）
- [ ] **云端流式抽样直存 Google Drive（不经过本地硬盘）**：
  - 使用免费 CPU Colab 实例挂载 Google Drive，通过 Hugging Face `streaming=True` 机房直连筛选高质量真人片段，打包成数 GB 精华包落盘至云端硬盘
  - 优先筛选：带自然口语停顿、嗯呃口水词、重复/改口、中英混说、科技/办公/日常访谈话题的片段
- [ ] **反向生成标注（仅回传几 MB 纯文本索引处理）**：
  - 用原版 `Qwen3-ASR-1.7B` 回检声学一致性，剔除标注与录音不符的脏样本
  - 用多模型双裁判流水线为真人逐字稿生成 `light` / `medium` 金标润色结果
  - 从逐字稿专有名词与话题反推逼真的 `<hotwords>` 与 `<screen>`，并混入 **30%～40% 完全无关的 `<screen>` 负样本** + **2%～3% 静音/键盘/底噪空输出负样本**
- [ ] **多任务混合配比（防声学遗忘）**：
  - `30%` 真人逐字 `<level>raw</level>`（声学锚）
  - `30%` 真人语音 → `<level>light</level>`
  - `30%` 真人语音 → `<level>medium</level>`
  - `10%` 自有真实听写录音（过采样补齐写代码/软件操作中英混说场景；暂不强塞高档重组与多意图）
- [ ] **最小闭环微调与本地盲评**：
  - 冻结 AuT Audio Encoder（初期一并冻结 Projector），仅对 Qwen3-1.7B 解码器做高秩 LoRA（`r=32~64`，`alpha=64~128`，`lr=2e-5~5e-5`），仅对 `<asr_text>` 之后的目标文本算 Loss
  - 合并权重并用 `transcribe.cpp` 转换脚本导出 `Q5_K_M` GGUF，零改动塞入本机在 **100% 真实麦克风录音测试集（≥ 60 条）** 上做盲评

### Stage 2：全量扩展与推理引擎升级（仅在 Stage 1 通过全部红线后启动）
- [ ] 将真人语音润色集扩至 1.5～2 万条并迭代 DPO / WiSE-FT 权重插值
- [ ] 在 `src-tauri/llm-engine` 为 `llama-cpp-sys-2` 开启 `mtmd` 特性（复用仓库内置的 `qwen3a`）：
  - 核对 `qwen3a` 在 Windows Vulkan 与 macOS Metal 下与 `transcribe-cpp` 的逐句精度一致性（重点检查非整秒音频 100 帧 padding 边界）
  - 将 `<level>` 放在固定前缀 `<scene>/<hotwords>/<screen>` **之后**、音频之前，利用纯 Transformer 的 `llama_memory_seq_rm` 实现 **O(1) 零拷贝前缀 KV 缓存**
  - 实现「说话中途 0.8s 预览（复用前缀 KV + `raw/light`）+ 内存缓冲整段 PCM + 松手按需重跑长段 `medium`」的分阶段路由
  - 保留 LoRA 开关能力，确保任何时候都能一键退回 100% 原版听写

| **WenetSpeech** | 10,000+ 小时中文播客/访谈/聊天，口音与口语极丰富 | `CC BY 4.0` | **可以**（需署名；留意底层媒体版权说明） |

### 2. 核心技术防坑清单
- **不要指望 0 训练靠 Prompt 让 `Qwen3-ASR` 润色**：官方技术报告明确它在 SFT 阶段被刻意训练成忽略 `system` 自然语言指令，必须微调覆盖。
- **不要解冻 Audio Encoder**：几千到几万条数据解冻编码器极易破坏千万小时预训练的声学泛化，应固定冻结 Encoder。
- **如果未来补录/补充少量 TTS，切忌直接把含错字的 `raw` 喂给 TTS**：必须先把“费尺/楼狗”这类 ASR 错字还原成英文 `fetch`/`Logo` 再配音，且坚持双引擎（CosyVoice 3 + Qwen3-TTS）+ 混响/底噪增广 + 原版 ASR 回检。
- **评测集铁律**：任何阶段最终验收都必须基于 **100% 真实麦克风录制的听写音频**，绝不用合成数据分数拍板。
- **产品定位克制**：不强迫 1.7B～2B 模型承担高档 30～90 秒跨句大改和多意图路由（`<edit>/<translate>/<define>/<ask>`），这类任务明确交给 4B 或云端。

### 3. 阶段 C 止损红线（任一条触发即停损或收缩为“增强轻档 ASR”）
- **R1 声学遗忘**：微调后 `<level>raw</level>` 在真实听写集上的 WER 比原版 `Qwen3-ASR-1.7B` 劣化 **> 0.5 个百分点**（即使加入 30% 真人 `raw` 与权重插值仍压不回）。
- **R2 润色质量不达标**：60 条真实录音盲评中，`light` 可用率 **< 80%** 或 `medium` 可用率 **< 65%**，或严重错改/漏关键信息/幻觉添句 **> 8%**。
- **R3 屏幕抄写 / 静音幻觉**：无关 1200 字 `<screen>` 抄写率 **> 2%**，或纯静音/按键底噪触发文字幻觉 **> 2%**。
- **R4 域迁移落差**：训练集/公开库表现优异，但本机真实听写录音测试集可用率跳水 **> 15 个百分点**。
- **R5 端侧速度不达标**：接入 1000-token `<screen>` 且开启前缀 KV 缓存后，4090 上 30 秒音频终态耗时仍 **> 900 ms**，或 M4 上 **> 1.5 s**。
