# 悬浮球百分比细条需对齐物理像素避免粗细不一

## 根因与证据

波形五条都设 `width: 10%` 仍不保证屏幕上等粗。百分比宽度、间距、居中及父级缩放会产生不同的小数像素相位；抗锯齿在各条两侧分配的覆盖率不同。

离线 Chromium 150% 缩放、69 CSS px 球体、原样式实测：每条约 3.646 CSS px，即 5.469 物理像素；截图同一中心行、相同颜色阈值统计得到 6/6/5/5/5 个着色像素。修复后同一测试为 5/5/5/5/5。该验证不等同于 Windows 桌面鼠标交互验收。

## 处理边界

- 在实际布局宽度、左坐标及 `devicePixelRatio` 上计算五条共用的整数物理像素宽度、间距和首条位置，再换回 CSS 坐标。高度继续表达音量，不把高度也强行统一。
- 悬停放大改变容器布局尺寸并重新测量，不能对已经对齐的细条再做 `transform: scale`。跨屏 DPI 变化重新订阅分辨率并测量，卸载时清理观察器。
- 等宽问题不能仅通过改颜色、加粗所有线条或换成静态图标掩盖。回归既检查几何计算，也检查实际截图中的像素覆盖。
- 声音重复与音色设计是两个问题：前者修复触发和接收路径，不擅自替换用户已认可的音效。具体约束见 `Tauri窗口emit是全局广播导致提示音重复播放.md`。

## 外圈描边的尺寸与缩放适配

- 固定 `1px` 是 CSS 像素，不是物理像素。Chromium 的细边框会按渲染密度取整；150% / 175% 实测旧描边都只剩约 1 个物理像素，小球圆周因而显得很细。仅换百分比也会随球缩小继续变细。
- 外圈按实际直径的 3% 取目标宽度，目标限制在 1.25～2 CSS px，再对齐物理像素且至少保留 2 个物理像素。最终 CSS 宽度允许有小数，光学上限也可能因取整略有超出。圆弧仍保留正常抗锯齿，不用关闭抗锯齿掩盖问题。
- 原生窗口已经按屏幕逻辑尺寸和用户比例计算球径，前端不可再重复乘屏幕分辨率。测量不带按钮入场缩放的外框，通过共享 `observeOrbGeometry` 跟踪尺寸、跨屏像素密度和动画结束。各状态复用描边宽度，只改变既有颜色，避免高亮时内容跳动。
- 静态渲染验证必须让浏览器实际渲染密度与 `devicePixelRatio` 一致；仅模拟 viewport 的 DPR 可能仍按宿主显示器密度取整 CSS border。独立 Chromium 使用 `--force-device-scale-factor`，且同一会话后续调用保留相同启动参数，否则工具可能重建空白页。这类截图不替代 macOS / Windows 外接屏的人工交互验收。
