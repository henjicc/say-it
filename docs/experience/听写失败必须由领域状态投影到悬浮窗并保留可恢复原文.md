# 听写失败必须由领域状态投影到悬浮窗并保留可恢复原文

实时 ASR、文件识别和智能处理都可能在主窗口隐藏时失败。只把错误写入终端或主窗口 Store，会让用户把网络、鉴权或模型错误误判成麦克风没有声音。

正确做法：

1. Rust 听写会话进入 `Failed` 时保存可读错误，并主动把错误投影到常驻悬浮窗；网络建连错误不得使用 `let _ = ...` 丢弃，也不得因“静音时断开连接”而退回等待声音。
2. 智能处理或后处理失败时，Rust 会话保留本次识别原文、冻结的注入方式和听写开始时的目标窗口。WebView 只展示“输入未处理原文/取消”并发送命令，不能持有恢复文本或自行决定会话状态。
3. 用户从悬浮窗选择输入原文后，先隐藏悬浮窗并重新激活听写开始时的目标应用，再执行注入；否则点击按钮改变焦点后，文本会被粘贴到悬浮 WebView 或应用自身。
4. 普通错误提供明确关闭操作；恢复成功、取消或新会话开始时必须清除错误和待恢复文本，避免旧会话内容泄漏到下一次听写。
