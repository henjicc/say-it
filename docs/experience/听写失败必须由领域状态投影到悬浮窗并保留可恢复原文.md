# 听写失败必须由领域状态投影到悬浮窗并保留可恢复原文

实时 ASR、文件识别和智能处理都可能在主窗口隐藏时失败。只把错误写入终端或主窗口 Store，会让用户把网络、鉴权或模型错误误判成麦克风没有声音。

正确做法：

1. Rust 听写会话进入 `Failed` 时保存可读错误，并主动把错误投影到常驻悬浮窗；网络建连错误不得使用 `let _ = ...` 丢弃，也不得因“静音时断开连接”而退回等待声音。
2. 智能处理或后处理失败时，Rust 会话保留本次识别原文、冻结的注入方式和听写开始时的目标窗口。WebView 只展示“输入未处理原文/取消”并发送命令，不能持有恢复文本或自行决定会话状态。
3. 用户从悬浮窗选择输入原文后，先隐藏悬浮窗并重新激活听写开始时的目标应用，再执行注入；否则点击按钮改变焦点后，文本会被粘贴到悬浮 WebView 或应用自身。
4. 普通错误提供明确关闭操作；恢复成功、取消或新会话开始时必须清除错误和待恢复文本，避免旧会话内容泄漏到下一次听写。

## 悬浮球错误态的交互边界

- 错误态需要同时开启原生窗口鼠标事件和前端按钮交互；只解除 `disabled` 无法修复原生鼠标穿透。
- 左键通过独立原生弹窗展示当次完整错误，不能把弹窗塞进悬浮球的小窗口。简短恢复提示不能替换底层错误原因，弹窗打开期间也不能被后续状态覆写或重复创建。
- 右键只清除悬浮球错误反馈，复用已有的延时失效、临时球归位/隐藏逻辑；不能调用听写取消命令，或删除、改写历史原文。已经恢复或进入新状态时，迟到的清除请求必须无效。

## 历史记录必须早于后处理

- ASR 完成后先写入 `recognized` 记录，原文和当前结果均为识别文本；必须早于上下文解析、LLM、本地规则和目标应用输入。继续遵守敏感目标、历史关闭及排除应用规则。
- 后处理完成后更新同一个 ID 的输出为 `processed`，输入结束再写终态；`source_text` 和创建时间不可被优化结果覆盖。
- 取消、错误只更新该记录，不重复创建；删除后的记录不能被迟到结果复活，终态不能被迟到处理覆盖。
- 启动时把遗留的 `recognized`/`processed` 标为未完成失败，并保留原文和已有输出，避免永远显示处理中。
- 历史页在后处理期间即可显示和复制原文，完成后能展开查看原文；待处理记录不能同时修正或重复注入。多次历史刷新须丢弃迟到的旧查询响应。
- 回归应覆盖关闭连接后原文仍可读、同条更新、处理/输入失败、取消、删除后的迟到结果、重启恢复及隐私开关，不以最终成功写入一条记录代替两阶段验证。

## 处理失败与交付降级必须分开

- ASR、本地规则或智能处理失败时，结果尚未完整生成，才进入 `Failed` 并提供原文恢复；目标窗口关闭、焦点目标失效或模拟输入失败发生在结果已经生成之后，属于交付失败，不得把整次听写标成失败。
- 交付失败时由 Rust 把最终结果写入剪贴板，并以成功降级状态结束会话和历史记录。悬浮指示器应明确提示“已经把结果放到你的剪贴板里了，你粘贴就可以用了”，不得展示红色错误操作区。
- 只有文本注入和剪贴板写入同时失败时才进入错误态；诊断日志仍应保留原始注入错误，并使用独立的 `clipboardFallback` 状态区分正常注入成功。
- 剪贴板降级提示的延迟隐藏必须绑定会话 epoch；用户在提示期间开始新听写后，旧计时器不得隐藏新会话的录音或处理状态。
