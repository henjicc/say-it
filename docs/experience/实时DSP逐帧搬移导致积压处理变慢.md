# 实时 DSP 逐帧搬移导致积压处理变慢

## 根因

`StreamDsp::process` 原先先重采样整包输入到临时数组，再追加到 `buf48`。每处理 480 个样本就 `drain(0..480)`，反复搬移剩余音频；单个输入包增大时，搬移成本近似按包长度的平方增长。输出又经过完整 f32 数组后才转为 PCM16，增加分配和复制。

## 修改

- 48 kHz 输入按帧复制；其他采样率逐样本插值后直接填入当前帧，保留原先的累计位置及浮点运算顺序。
- 采样工作区固定为三个 480 样本数组：当前帧及 RNNoise 输入、输出，共 5760 字节；响度计与降噪器自身状态另计。
- 帧内就地降噪、EQ，随后按原先的响度回退、增益平滑、限幅和三抽一平均处理，直接写 PCM16 返回数组。
- 不补零未满的最后一帧，不改变采样率、处理质量或输出时序；返回数组仍按本次实际输出大小分配，不能把“固定工作区”误称为整个 API 的内存恒定。

大包是积压压力用例，不能把该收益当作日常小包收益或整套应用 CPU 降幅。额外注入 30 分钟音频（4096 样本一包、关闭降噪），修改后私有提交峰值中位数 4.03 MiB，输出哈希稳定；没有增加磁盘或跨进程存储。

所有前后对照场景的输出长度与哈希一致。`audio_dsp/stream_reference.rs` 仅在测试中保留优化前算法，覆盖 8～192 kHz、零采样率默认行为、多种分包、单样本包、空包、未满尾帧、降噪、语音门、EQ 和增益参数，并逐调用比较 PCM 字节。该参考代码不得随生产缓冲重构同步修改。

额外的 30 分钟开启降噪输入前后各运行一次，输出哈希均为 `8e6c90e9de859c94`；优化后测试进程峰值私有提交 4.05 MiB。该组与应用构建同时运行，仅用于长序列正确性及内存检查，不作为耗时收益依据。完整 Rust 发布配置回归结果为 578 项通过、10 项显式忽略、0 项失败。

复现：先 `node scripts/run-rust-tests.mjs --release --no-run`，再调用 `scripts/measure-audio-performance.mjs --scenario realtime-dsp --executable <测试程序> --output <结果.json> --seconds 60 --runs 3 --sample-rate 48000 --packet-size 4096`；开启降噪追加 `--denoise`，大包测试改为 `--packet-size 480000`。JSON 记录测试程序 SHA256。
