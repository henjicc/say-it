# 模型包安装与启动时反复整份哈希大文件

## 现象

- 双击一个 2.7 GB 的内嵌模型包，「正在校验插件清单、文件完整性与签名…」要转很久，数据盘是机械硬盘时以分钟计，期间内存还会涨几个 GB。
- 装了几个本地模型后应用启动变慢。

## 根因

校验写成了「每到一个环节就整份再算一遍」，而且用 `std::fs::read` 把文件整个读进内存再算：

- 预览：整包算哈希 → 全部解到暂存目录 → 整包再算一遍（确认没被换）→ 对照完整性清单逐个文件算。
- 安装：再全部解一遍 → 整包再算 → 校验 → 整个目录复制到另一个暂存目录 → 再校验 → 移动模型文件前校验 → 装完再校验两遍。
- 启动和每次重载插件：`verify_installed_model_pack` 把每个已装模型包的权重整份读一遍；校验结论只记在内存里，重启就没了。

同一份内容前后读了八遍左右、写了三遍。

## 做法

底线只有两条：没签名或签名不受信的包要用户确认；装进来的文件内容必须和签过名的清单一致。守住这两条不需要重复读。

- **哈希记录**（`providers/model_download.rs`）：1 MB 以上的文件按「大小 + 修改时间」记下 SHA256，存在数据目录的 `model-file-hashes.json`。文件没被改写就沿用，不按路径记，所以安装过程中在暂存目录之间改名移动后记录仍然有效。
- **解包时边写边算**：写完直接记下哈希，之后对照清单不用再读。
- **预览不碰大文件**：超过 8 MB 的条目不解出来，只解析清单并验签名。「这是什么、谁签的」靠清单和签名就能回答，内容在安装时校验。
- **预览和安装之间**用包文件的「大小 + 修改时间」发现文件被替换，不再整包算哈希。
- **安装源是自己解出来的暂存目录时直接改名移动**，不复制、不二次校验。

结果：安装时整包读一遍、写一遍；装好之后启动只做文件属性查询。

## 注意

- 哈希记录认的是「大小 + 修改时间」。有人拿到本机文件权限、把权重换成同样大小并改回修改时间，校验会被骗过；这属于本机已被攻破的情形，不在设防范围内。
- 小文件不进记录：算得快，而且同一批解出来的小文件更容易撞上相同的大小和修改时间。
- 新增「写大文件」的路径（比如下载）时，写完调用 `record_sha256`，否则第一次校验还是会整份读一遍。
