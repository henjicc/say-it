# 原生字幕单句布局居中导致文本落在可视区外

## 现象与根因

原生字幕背景正常，文本已送达，DirectWrite 布局和绘制调用均成功，但看不到文字。
单句模式用百万 DIP 宽的布局框测量自然宽度，同时继承了文本格式的居中对齐。
`GetMetrics().width` 只反映内容宽度，遗漏的 `left` 已接近 500,000 DIP；后续按内容宽度平移，仍无法把字形移回裁剪区域。

单句布局应使用 leading 对齐，由 `replace_offset_x` 唯一负责短句居中和长句贴右。
滚动模式仍在实际可视宽度内居中换行。不要为了修这个问题删除统一行距或扩大裁剪框。

## 验证与相邻问题

- 回归测试先复现 `left=500005.38`、可视宽度 `400` 的失败，再验证修复后的短句和长句实际边界。
- 软件 D2D 绘制到 DIB 后检查两条轨道的文字像素，覆盖双语、换行、宽度/行数变更和淡入结束。测试不需要识别服务、翻译服务或鼠标操作。
- 字体、模式、宽度、行数及窗口宽度变化，都要重新测量两条轨道并更新滚动目标。
- 悬停启动动画后必须在渲染之后同步定时器；否则首帧透明度为零且没有后续帧。
- `SAYIT_NATIVE_SUBTITLE=0` 必须显式路由到 WebView 显示分支，不能被原生胶囊的默认隐藏分支接管。
- 按需创建的 WebView 会错过首次配置事件；等待配置、状态、原文、译文订阅全部就绪后，再向 Rust 请求当前投影。就绪重投影不能抢占原生字幕或听写。
- 原生与 WebView 的锚点必须使用同一显示器边界。WebView 按完整屏幕尺寸定位时，原生不能改用扣除任务栏的工作区。
- CSS 缓动应反解三次贝塞尔的时间坐标；直接使用 easeOutCubic 会明显改变相同持续时间下的动画进度。
- D2D 画刷颜色使用 straight alpha，DIB/位图才使用预乘 alpha。字幕半透明文字和边框不能在画刷输入阶段重复预乘。
- DC 渲染目标不支持效果管线时，整段切换的模糊可在临时软件 DIB 上完成，使用现有 image 库对预乘像素卷积；只在动画期间创建，完成后释放，避免常驻 GPU 设备。临时画布需在可视区四周保留三倍 sigma。

屏幕截图使用 PIL ImageGrab；枚举窗口前先设置 Per-Monitor DPI Awareness，避免物理像素与虚拟坐标混用。
