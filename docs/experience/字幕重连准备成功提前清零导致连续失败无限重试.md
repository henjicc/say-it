# 字幕重连准备成功提前清零导致连续失败无限重试

## 触发与根因

关闭字幕静音断开时，ASR 结束/报错会进入自动重连。原实现每次 `open_asr` 准备会话后立即把 `reconnect_attempts` 清零；真正的插件/服务启动和音频处理尚未完成。若每次连接都在收到音频后报错，下一次失败总被算作第一次，六次重试上限永远无法触发，造成后台反复创建识别任务。

完整应用本地验收首次以 `实时领域未结束` 失败；代码检查发现计数在异步启动前清零。失败记录保留在忽略目录 `工作区/performance/subtitles-app-1`，不得当作成功数据汇总。

## 修正边界

`subtitles/reconnect.rs` 独立保存重试次数和本次会话开始时间。准备新会话仅更新时间，不重置次数；收到非空识别文字时恢复预算。没有文字但持续至少 30 秒的会话，在断开时也按新一轮计数，避免把相隔很久的正常断开永久累加。这个时间条件是重试策略，不是网络握手成功的证明。

连续短连接失败保留既有六次重试上限和递增等待；超过上限后沿原来的停止/失败流程释放采集、音频租约和识别任务。正常停止、按静音等待语音的模式、翻译重试策略均未改动。

## 回归方式

单元测试覆盖反复准备失败连接、空白文字不得恢复预算、有效文字恢复预算、30 秒边界及长时间安静后的断开。应用验收必须持续送入本地音频，确保每次重连都真正触发模拟服务失败；仅送两秒音频后等待，会让后续连接停在等待输入，不能证明重试已经结束。达到失败终态后，必须验证采集/队列/租约释放、识别登记清空，并再次成功启动和显示字幕。

## 验证结果

2026-09-25，725 项 Rust release 测试通过，0 失败、32 项专用用例默认忽略。应用验收 `工作区/performance/subtitles-app-2`，SHA256 `AF76B5DDE9B73F5FB6C5B24BA82A0755B93AB9513FF2EFB4688032EF2DB2B84F`，三轮成功、持续失败、再次成功，共九个任务全部通过。持续失败约 6.84～6.87 秒后到达失败终态，采集 worker、音频队列、音频租约及 ASR 登记均释放；后续任务实际显示测试字幕。正常停止命令到收敛约 0.18～0.25 ms，不代表屏幕首帧时间或真实识别服务速度。

同轮包含自动空闲堆回收：初始私有提交 6.88 MiB，三轮闲置分别 16.32、17.20、17.66 MiB，最终 17.58 MiB；观测峰值 23.78 MiB，最终 34 线程、275 句柄。三轮末默认堆活分配为约 4.56、5.04、4.90 MiB，不能把提交量上升直接解释为活对象泄漏，也不能据三轮断言无限运行不增长。退出后无残留子进程。实时字幕、原生展示及清理使用正式路径，输入和服务来自无网络权限的本地模拟；本轮没有开启翻译或 OBS，不覆盖真实服务识别质量、屏幕字形或 macOS。
