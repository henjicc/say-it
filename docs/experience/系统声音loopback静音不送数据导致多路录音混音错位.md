# 系统声音 loopback 静音不送数据，导致多路录音混音错位

## 现象

同时录麦克风和系统声音（会议记录），两路按样本序号直接相加后，系统声音那一路的内容整体提前，越往后和麦克风错得越多。

## 原因

Windows WASAPI loopback 在没有任何声音播放时不产生数据包，静音段在采集层就不存在。两路都按「收到多少写多少」落盘，系统声音那一路就比实际经过的时间短，之后的内容被拼到前面。两个设备的时钟本身也有漂移。

## 做法

- 每一路收到数据包时，按墙钟算出这一路「应该写到哪」，落后超过容差（`application/meeting.rs` 用 200ms）就先补静音，再写这一包。
- 容差要大于采集层一包的时长（`backend_mic.rs` 按 4096 帧攒包，16kHz 时约 256ms 一包；按「到包时刻」计算即可）。
- 代价：设备时钟比墙钟慢时，长录音里每累计落后一个容差就会插入一小段静音。
- 混音测试不能只测「短的一路结尾补静音」，那样测不出中途的错位。
