# 云端大模型识别前不应过 RNNoise 降噪与自适应增益，48k→16k 抽取需抗混叠

## 现象

用 Gemini Live Translate 做实时字幕，识别错字多、译文跟着跑偏；看带 BGM 的日语视频时尤其明显。协议层 `setup` 报文核对无误，官方也不开放源语言、系统提示等可调参数，问题不在配置。

## 根因

1. 送入 Gemini 前先过了为本地小模型设计的整套 DSP：RNNoise 全湿降噪（默认强度 100%）+ 响度归一化（最大 +40dB）。云端大模型自身对噪声鲁棒，RNNoise 带来的频谱空洞、吞字、把音乐/背景声抹掉反而削薄人声；自适应增益在静音段把底噪顶到 -20 LUFS，等于给模型喂噪声。
2. 48k→16k 下采样只是三点盒式平均（`dec_acc / 3`），没有抗混叠低通。12kHz 的内容只衰减约 -10dB 就折叠到 4kHz 语音频段，形成"沙沙"的混叠噪声，所有 16k 云端模型都受影响。

## 修复

- `audio_dsp.rs` 新增 `Decimator3`：95 抽头 Blackman 窗 sinc 低通（截止 6.6kHz）+ 三抽一，只在抽取点卷积。实测 6kHz 以下 0dB，8kHz 起 ≤ -55dB。本地与云端链路统一使用。
- 新增 `StreamDsp::passthrough(in_rate)`：跳过降噪 / EQ / 增益，只做重采样与抗混叠抽取，电平原样送出。`gemini_session.rs` 改用它，用户的降噪/响度参数对 Gemini 不再生效。

## 判别方法

设置 → 高级 → 响度与降噪 → 关闭"启用降噪"后对比准确率；明显变好说明是前置 DSP 在害识别。新增 `audio_dsp::tests` 用 1kHz / 12kHz 单音分别断言通带增益与阻带衰减，防止抽取器回退成盒式平均。

## 原则

- 为本地小模型调的前置处理不要默认套到云端大模型上；新增云端供应商时优先用 `StreamDsp::passthrough`。
- 任何降采样都必须先低通再抽取；"取平均"不是抗混叠。
