# 实时字幕译文历史无限保留与全量拼接的回收边界

## 原因

`TranslationDocument` 的滚动组虽然只保留 12 组，`values` 却没有删除失去引用的译文。替换模式连续说话时，`replace_groups` 也不断增长。每次渲染先复制并拼接所有历史，再截取末尾 1,800 字符，导致会话越长，刷新成本越高。

## 实现边界

- 渲染从最后一组、最后一个字符逆向读取，只收集可见尾部；滚动模式仍按非空译文组计算行数。
- 每个结果保留末尾 1,801 字符。多出的一个字符用于区分“刚好填满”和“确实截断”，保持旧逻辑仅在截断时 `trim_start` 的行为；不能在各个片段内部提前修剪空白。
- 使用现有翻译事件的 `done` 标记确认文本稳定。流式 partial 可能在 final 时缩短，因此不能依据 partial 长度回收旧历史。
- 一个组内或替换组序列的后方已经拥有 1,801 个已完成字符时，前方内容不可能再次进入显示尾部，可以移除。空的已完成结果可以移除；滚动模式的 12 组位置仍保留。
- `values` 和完成标记仅保留当前组、滚动历史组、替换组共同引用的条目。已淘汰结果的迟到事件不能重新插入，已完成结果也不再接受后续改写。
- 翻译失败沿用先前 partial 的显示结果，并将该请求标为完成，以便释放已经没有用途的历史。

这条路径只负责实时字幕显示，并不存储转写文件或录音历史；没有截断持久化文档或音频。

## 验证

2026-09-24 Windows x64 发布配置：680 项 Rust 测试通过，26 项忽略，无失败。新增覆盖乱序流式返回、final 缩短、长句没有 commit、空结果、迟到结果、Unicode/空白边界、切换模式。对照旧实现逐事件比较替换模式及滚动 1/3/12 行输出。

`scripts/measure-audio-performance.mjs` 新增 `subtitle-retention` / `subtitle-retention-legacy` 场景。同一测试二进制的旧逻辑和新逻辑分别运行 3 个独立进程，每次提交并显示 4,000 段合成译文，不调用设备或服务：

## 仍需单独处理
