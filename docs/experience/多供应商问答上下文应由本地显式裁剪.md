# 多供应商问答上下文应由本地显式裁剪

## 适用场景

同一套智能问答需要同时兼容 Chat Completions、Responses API 以及其他 OpenAI 兼容供应商，并要求确定性限制保留轮数。

## 结论

- Chat Completions 的上下文由客户端在每次请求中重发累计的 `messages`。
- Responses API 可使用 Conversations API 或 `previous_response_id` 维护服务端状态，也接受客户端显式发送历史消息；使用 `previous_response_id` 时，顶层 `instructions` 不会自动继承，仍需每次重发。
- 多供应商桌面应用优先在本地保存交替的 user/assistant 轮次，按产品上限裁剪后随请求显式发送。这样不依赖供应商会话 ID，Chat 与 Responses 可共享同一行为，也便于窗口关闭时立即清空上下文。
- “保留最近 10 轮”应在一轮成功完成后追加，并从队首删除超出的旧轮次；失败、取消或未完成的输出不得写入历史。

## 注意事项

- 历史消息仍会计入输入 token，裁剪轮数不能替代 token 预算控制。
- 系统指令必须独立于历史消息，每次请求明确发送，不能假设远端会话会继承。
- 重新生成当前轮时，应使用该轮之前的历史，成功后替换当前轮，而不是把失败或旧答案额外追加成新一轮。
