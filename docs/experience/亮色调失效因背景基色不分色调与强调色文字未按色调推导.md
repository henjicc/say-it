# 亮色调失效因背景基色不分色调与强调色文字未按色调推导

## 现象

默认配置下在「外观」切到亮色调：整窗仍是深底，页面标题、分段按钮选中段和标题栏品牌名几乎看不见，检查器变成中灰。用「柔和背景」时能用，但次要文字、链接（`accent-light`）、状态色在浅底上对比不足。

## 原因

- 主题里的「背景基色」只有一份、不分色调，而默认值是暗色的 `#0F0F0F` 且默认模式就是自定义背景。切到亮色调后，层级推导按亮色规则去混白混黑，输入却是深色，整套层级与文字色一起失效。
- 强调色的文字用法直接写死 `--color-accent-light`（为深底调的浅蓝），亮色下再靠零散的 `[data-ui-tone="light"]` 覆盖改成 `accent-dark`；状态色、阴影、遮罩也只有暗色一套，另有按类名子串匹配的 `!important` 补丁。

## 正确做法

- 只随色调变化的令牌（文字层级、状态色、线、阴影、遮罩）集中在 `useThemeStore` 的 `TONE_PALETTE`，层级色由 `themeLayers` 从背景推导；不要在 CSS 里按 `data-ui-tone` 打补丁。
- 背景基色必须与当前色调同侧（`backgroundTone`：黑字比白字更清楚即为浅色背景），相反时在 `normalizeTheme` 换成该色调的默认背景。新输入另用 `backgroundSupportsText` 拦截（同侧且最浅可读文字在内容层上达到 AA）。不要拿各层都达 AA 这种严格阈值去筛已保存的背景：`#282C34` 这类常见深色背景会被误判，回写后无法恢复。
- 强调色按用途分三种令牌：`accent` 做无字填充，`accent-control` 做带字填充（主按钮与所有选中态），`accent-text` 做文字与图标（暗色提亮、亮色压暗，保证在各层及叠了柔和强调底的各层上达到 AA）。新写强调色文字一律用 `accent-text`，焦点环 `--accent-ring` 同色。
- 改默认主题值时同步 Rust `default_theme()`，并把旧默认值加进 `superseded_default_themes()`，否则老用户停在旧默认、首次导入时 localStorage 镜像还会把旧值写回。
