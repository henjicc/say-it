# 百炼实时识别空中间帧误判与无文字失败历史遗漏

## 触发与证据

2026-09-24，`qwen-audio-3.1-asr-flash-streaming` 一开口即报
`[invalid_response] Bailian Fun-ASR result has no text or sentence state`。
合法的 SDK 0.6.0 最小输入配合合成语音直调即可复现，排除了 Rust/QuickJS 输入转换。

服务端在句首事件之后还会发送 `text=""`、`sentence_end=false`、
`end_time=null`、无 `sentence_begin` 的中间帧。句首标记仅用于第一帧，
不能要求所有空文本中间帧都携带它。该模型复用 Fun Duplex 协议，
因此错误中的 Fun-ASR 名称不代表当前选择了 Fun-ASR 模型。

## 修复边界与回归

- 公共解析在 Henji-AI 的 SDK 源头修复：允许有字符串 text 且明确非终态的空中间帧继续等待。
  缺少 text、空 final、结束前全程无 final 仍需明确失败；宿主不复制供应商 parser。
- 听写失败时，即使尚无文字也保存真实失败状态、完整错误和模型；错误不能冒充识别文字。
  已有历史只更新同一条记录，历史总开关、排除软件及敏感窗口限制继续有效。
- SDK 的脚本化事件序列和宿主 QuickJS/WebSocket 回归均应包含“句首 → 空中间帧 → 文字 → final”。
  历史回归覆盖空失败落盘、空成功拒绝、已有记录复用和隐私限制；界面禁用无文字的复制/修正/注入。
