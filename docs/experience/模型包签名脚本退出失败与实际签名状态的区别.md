# 模型包签名脚本退出失败与实际签名状态的区别

`sign_plugin.py` 在写入 Ed25519 签名后调用 `validate_plugin.py::validate`。该校验入口只接受 `sayit-package.json.kind=provider-plugin` 和 JavaScript runtime，因此对 `model-pack` 报错并以非零状态退出，即使写出的签名已经有效。不能单凭退出码认定包未签名，也不能把签名存在当成验签通过。

官方模型包优先使用 `build_model_pack`，构建器会直接签名。若另外运行了 Python 签名脚本，必须保留其失败原因，对最终归档重新执行宿主验签，不能关闭校验或修改清单类型来通过 JavaScript 校验器：

```powershell
$env:CARGO_TARGET_DIR='D:\VibeCode\说吧\src-tauri\target'
$env:SAYIT_MODEL_PACK_ARCHIVE='<最终 embedded.sayit 的绝对路径>'
cargo test --manifest-path src-tauri/Cargo.toml --bin say-it builder_archive_matches_host_signature_and_integrity_contract -- --ignored --nocapture
```

该用例使用临时目录，验证完整性、Ed25519 签名、安装后的权重校验及篡改拒绝。空信任库返回 `signed-untrusted`，表示签名有效但测试未信任该公钥；不是 `unsigned`。Python 的 `validate_integrity` 可作附加签名检查，不能替代宿主对模型包结构和安装契约的验证。
