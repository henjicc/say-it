# 模型加载线程切后台模式导致加载慢十倍

## 现象

用本地识别模型听写，说了十几秒一个字都没有，报「识别模型一直没有准备好，这次没有识别结果」。开发者追踪里整段录音没有任何 `localAsr.*` 事件。

## 原因

加载线程用 `SetThreadPriority(THREAD_MODE_BACKGROUND_BEGIN)` 切到了后台模式，本地识别模型（`local_asr/cache.rs`）和整理模型的推理进程（`llm-engine/src/engine.rs`）都这么做过。初衷是加载时别让悬浮窗和录音卡顿。

后台模式不只降处理器优先级，还把这个线程的磁盘读取和内存换页优先级降到最低。加载要读几 GB 权重，每次缺页都排在所有其他读写后面，机器上只要有别的程序在读写磁盘就会被拖住。追踪里的加载耗时：

| | 改动前 | 改动后 |
| --- | --- | --- |
| 识别模型（Qwen3-ASR 1.7B） | 约 3 秒 | 37～48 秒 |
| 整理模型（4B） | 约 3～4 秒 | 10～88 秒 |

## 做法

加载线程保持正常优先级。加载期间的短暂卡顿（两三百毫秒）远比开口后几十秒没有结果好接受。要缓解卡顿，换别的办法（比如提前预载、常驻），不要再降加载线程的读写和换页优先级。

排查「没有识别结果」时，先看追踪里 `localAsr.loaded` / `localLlm.loaded` 的 `loadMs` 有没有突然变大。
