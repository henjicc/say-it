# 本地整理推理进程开了显卡采样后读不到标签概率

适用：想给本地整理模型的意图标签加置信度门槛（`docs/task/本地模型多任务微调/01-训练数据规范.md` 要求「低于门槛按听写处理」）。

## 现象

`llm-engine/src/engine.rs` 在上下文上挂了显卡端的贪心采样器（`params.samplers`），每个位置只把选中的 token 读回内存，不再拷整张词表的分数。这时：

- `llama_get_logits_ith` 先找采样器给出的分数，贪心采样器不产出分数；再找原始分数，而 llama.cpp 在所有序列都用显卡采样时不拷原始分数（`needs_raw_logits` 返回假），所以拿不到。
- `llama_get_sampled_probs_ith` 只有 `dist` 这类会算 softmax 的采样器才有值，贪心没有。

所以不改推理进程，就拿不到标签那个 token 的概率。

## 可选做法（未实现）

- 在采样链里贪心之前加显卡端的 `top_k`，再读 `llama_get_sampled_logits_ith` 和 `llama_get_sampled_candidates_ith`，用前 k 个分数做 softmax 来近似概率。这样每个位置都多一次 top-k，要先在 M4 和 4090 上量一下单次前向涨了多少。
- 只在第一个输出位置临时去掉采样器（`llama_set_sampler(ctx, 0, null)`）读原始分数。但切换会让调度器重新预留缓冲（`sched_need_reserve`），每次整理都要付这笔开销。

目前应用侧没有概率门槛，靠两条规则兜底：模型判成指令却执行失败、或要改选区却没有选区时，强制 `<dictate>` 再整理一遍；有选区时执行失败只报错，不插入，因为插入会覆盖选区。
