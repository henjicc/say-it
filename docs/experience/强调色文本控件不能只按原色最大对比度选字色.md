# 强调色文本控件不能只按原色最大对比度选字色

## 适用场景

当按钮、导航选中项、分段控件等使用用户自定义强调色作为填充时。

## 问题

直接比较黑白两种字色在原始强调色上的对比度，会让 `#5199FF` 这类中等亮度的高饱和蓝色选中黑字。数值对比度虽然更高，但不符合桌面端主操作控件的视觉语义，并且会在同一界面中显得突兀。

## 正确做法

- 原始强调色保留给滑块、进度条、边框和其他无文字装饰。
- 文本型强调控件使用独立的语义填充令牌：中深色、高饱和色优先白字，只有真正的浅色才使用黑字。
- 如果选定字色后对比度不足 WCAG AA，只对文本控件填充做最小幅度的明暗修正，不要改变用户选择的原始强调色。
- 主按钮、活动导航、选中 Tab、下拉选中项和复选框必须共用同一组语义令牌，避免同一强调色产生不一致字色。
