# 听写取消需同时结束模型等待与后台插件执行

## 触发条件与原因

听写事件接收循环串行等待 `finalize`。原有会话编号校验可以阻止旧结果注入，但上下文提取或模型请求未返回时，旧的 `finalize` 仍占用事件消费者，取消后新会话的事件可能排在旧请求后面。

另外，丢弃等待 JavaScript 工作线程的异步 Future 不会自动终止该线程。只缩短上层等待，仍可能遗留网络请求、脚本运行时和关联资源。

## 修复边界

- 每个听写会话拥有独立处理取消令牌；取消、失败和会话替换时通知旧令牌，新会话重新创建令牌。
- 仅对可以放弃的上下文提取、助手处理和智能处理等待使用取消选择；取消后执行原有资源清理。原文保存、注入提交、会话编号和目标窗口安全校验继续保留。
- 等待独立 JavaScript 工作线程时持有取消守卫；调用方 Future 被丢弃时设置并通知底层取消标记，让现有运行时取消与处置路径收尾。
- 通用插件接口可能与外部调用方共享取消标记，正常返回前必须解除守卫。否则一次成功请求也会被外层识别为取消，例如文件识别可能因此不再发布完成事件。
- 不通过为每个事件另起任务解决串行等待，避免破坏事件顺序或引入无上界并发。

## 验证与限制

2026-09-24 发布配置 Rust 回归：675 项通过，25 项忽略，无失败。新增覆盖预先取消不启动处理、正常结果与错误保持、取消解除串行等待、失败后新会话令牌独立，以及共享取消标记正常完成后保持未取消。

本地挂起插件集成测试设定 60 秒运行超时，在调用方被放弃后，要求工作线程在 2 秒测试窗口内注销，并验证处置回调确实写入测试存储。该测试不主动排空插件命名空间，避免测试代码替被测逻辑取消线程。所有新增测试均不请求真实供应商。

这些证据验证取消传播和资源收尾，不等同于真实供应商响应延迟、整机内存收益或完整桌面交互验证，也不保证供应商服务器停止已经收到的请求。
