# SQLite 每次新开连接在机械硬盘上反复合并 WAL 拖慢听写

## 现象

开发者追踪里「保存原文」阶段稳定 170～220ms，「输出到目标软件」也偏长；单独在 SSD 上测写一条历史只要约 11ms，对不上。

## 原因

`history.rs` 每次读写都新开一条连接。WAL 模式下，最后一条连接关闭时 SQLite 会把 WAL 合回主库并删除 WAL，下一次写入再重建 WAL，两步都要同步落盘。数据目录在机械硬盘（用户的 E 盘）上时，一次写入约 140ms；同时还有别的连接开着时只要约 3ms，所以只在「最后一条连接」时出现。

## 做法

- `open_path` 给每条连接设 `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE`，关闭时不合并；WAL 满 1000 页时由提交自动合并，`journal_size_limit` 截到 4MB。
- 迁移前的 `wal_checkpoint(TRUNCATE)`、迁移与重置清单都已包含 `-wal` / `-shm`，持久化 WAL 不影响它们。
- 排查这类耗时：先看追踪里的阶段细分，再在**用户实际数据目录所在的盘**上复制一份数据库计时，不要只在开发盘上测。
