# 实时识别积压的内存与临时文件双重预算

## 根因与处理范围

文件投喂可以暂停等待识别，但麦克风和系统音频发送路径不能等待慢模型或网络。此前实时 ASR 输入仍使用无界内存队列；原生推理、模型初始化或网络消费落后时，音频会持续堆积。本次约束 ASR 输入队列，不修改采样内容、DSP、识别模型或供应商协议。

正常短队列保留原有内存传递，不创建临时文件或后台写盘线程。排队的驻留音频超过 2 MiB 后，新增音频交给按需创建的独立阻塞写盘线程，以最多 8 MiB 的文件段存放原始 f32 位值。发送路径只做计费、有限复制和入队，没有文件 I/O，也不等待消费者。单个原始输入暂时保留到入队完成，以便接收器关闭的竞态下仍能把原包还给采集层。

## 容量与所有权

以下均为每个识别会话的预算，不是应用总内存上限：

- 队列内和待写盘任务持有的浮点分配容量合计最多 64 MiB；使用 Vec.capacity() 计费。
- 逻辑积压（分配容量及消息包装）最多 512 MiB；消息最多 32768 个；单包分配最多 64 KiB。目前生产采集按最多 4096 样本分块。
- 临时文件段实际保留的数据另有 512 MiB 预算。已消费包可能与未消费包共用文件，所以不能只靠逻辑队列长度约束磁盘。
- 超限、线程启动失败、写入失败或文件不完整都使任务明确失败，不能静默丢音频后继续报告成功。
- 可暂停的文件输入仍使用 64 KiB 等待预算，不会因此落盘。

上述浮点预算不包含发送方持有的原包、入队时的短暂副本、已取出的处理包、消息元数据、线程栈、模型和系统文件缓存；消息数量与单包上限另行约束相关开销。多个会话的预算相加，不能把单会话上限当作全进程上限。

首轮暂存由文件段所有者在 Rust 析构中删除路径，后续已改为由操作系统按文件句柄生命周期回收，见下方“异常退出清理”补充。文件句柄必须先关闭，再归还文件预算。取消优先于积压，接收器关闭票据后后台线程跳过未开始的写入并退出；已经进入操作系统的同步文件 I/O 不保证可立即中断。

## 异步与失败边界

Apple 的外层 select 可能放弃尚未完成的 recv future。已经取出的磁盘票据和异步读盘票据必须留在接收器 pending 字段，不能只保存在临时 future 中，否则下一次接收会丢包。异步接收的实际文件读取交给阻塞线程。

暂存失败同时设置原有取消标记，以便打断正在执行的 SDK 宿主操作。初始化失败和正常退出都发送结束事件；模型对比的结束处理必须保留此前的错误状态，且不得影响已替换的新会话。

## 仍需单独处理的边界

- 原始采集订阅队列已由下文的后续修复接入同一预算；音频调校素材已由后续分块存储改造限容，模型对比初始化期间的缓存仍需单独处理，不能据此宣称整条音频管线已全部有界。
- Windows 进程被强制终止、跳过 Rust 析构的退出已由后续修复覆盖。操作系统崩溃、突然断电及特殊文件系统故障不在本轮实测范围内；不能把进程退出测试扩展为这些场景的保证。
- macOS 运行时与真实设备/供应商未在这台 Windows 机器验证；本轮证据是本地合成数据与 Rust 回归，不是所有平台端到端认证。


## 异常退出清理补充

普通 Rust 析构不会在进程被强制终止或 process::exit 时执行。暂存写入磁盘后，不能只依赖 Segment::drop 中 remove_file；这会留下原始音频，也可能跨重启累积存储占用。

现在每个文件段持有一个文件句柄，写入器与待读票据共同拥有它。Windows 使用 FILE_FLAG_DELETE_ON_CLOSE，且共享模式为 0，避免其他进程按路径打开文件并延长其寿命；最后一个句柄关闭时由操作系统删除文件。Unix 在成功打开后、写入音频前立即移除目录项，后续只使用已打开的句柄。此处没有启动扫描或批量删除旧文件，也没有新增依赖。[Windows CreateFileW 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[Rust remove_file 文档](https://doc.rust-lang.org/std/fs/fn.remove_file.html)。

读写双方共用文件句柄后，每一次读取和写入都必须带绝对偏移，并处理短读、短写与中断。尤其 Windows seek_read / seek_write 会改变文件游标，不能再混用依赖共享游标的 seek + read/write，否则并发读取旧包时可能改变下一次追加的位置。[Rust Windows FileExt 文档](https://doc.rust-lang.org/std/os/windows/fs/trait.FileExt.html)。

新增回归在隔离测试目录中启动独立测试进程，分别停留在空文件、持有两段音频、已读取首包但仍持有其余票据，以及 process::exit(73) 四种状态，每种重复三次。父进程对前三种状态直接强制结束子进程；确认子进程结束后，先断言目录里没有暂存文件，再执行测试目录自身的清理。12 次均通过，不能用测试自己的删除来掩盖遗留。另验证并发读写 1000 个音频包仍保持顺序及 NaN / 负零位值，并验证暂存音频无法按路径重新打开。

完整 Rust release 回归 621 项通过、0 项失败；18 项用例显式忽略，其中新增的隔离子进程入口由父级回归明确调用。真实设备和供应商未调用，macOS 运行时仍未验证。

| --- | ---: | ---: | ---: | ---: |
| 5 分钟积压 | 8.39 MiB | 8.75 MiB | 66.04 ms | 61.33 ms |

30 分钟三次新峰值为 12.13～16.07 MiB，待写浮点缓冲最大观测为 4.38～6.88 MiB，仍在每会话 64 MiB 预算内；保留音频时私有提交为 11.31～12.36 MiB，释放后中位数约 5.92 MiB。此次生命周期修复不是进一步压低峰值的优化，短暂写入积压和文件句柄需要一起计入代价。

## 原始采集订阅与停止排空补充

仅限制 ASR 输入仍不足以约束采集积压：听写录音、字幕静音检测、模型对比和音频调校原先通过另一个无界 raw 通道读取原始音频。写盘、模型初始化或处理线程短暂停顿时，这一层仍会积累浮点数组。

麦克风与系统音频订阅现在复用 AsrInputSender 的短队列、驻留字节和临时文件预算，通过 RawAudioReceiver 返回 Result<Option<Vec<f32>>, String>。正常 EOF、完整音频和失败必须分别处理；设备故障直接传入订阅通道，不能只依赖可能已被停止清理重置的 last_error。采集回调不做文件读写，不等待消费者。每份订阅独立计费：64 MiB 浮点驻留、512 MiB 逻辑积压与 512 MiB 实际暂存文件预算不是整个进程的统一预算，也不包括消费者已取走的素材。

音频调校原先在设备停止后立即将 recording 置为 false，消费任务随后读取的尾包会被 append 忽略。现在先关闭采集发送端，继续接收完整尾部，等待消费任务交付结果，再结束会话。停止排空最多等待 10 秒；缺少消费任务、任务提前退出或暂存失败均显式失败，不把不完整素材当作成功录音。开始、停止与故障清理由同一操作锁串行化，每次录音有独立 epoch；旧消费任务不能追加到新素材，也不能释放新会话的设备。消费任务必须先发送排空结果，再获取清理锁，否则会与持锁等待结果的 stop 互相等待。

本地回归覆盖同步/异步读取暂存后正常 EOF、17 样本尾包、负零位值、实际文件写入失败、设备失败优先上报、丢弃接收器后取消、失败订阅不影响健康订阅、停止等待延迟尾包，以及旧会话追加/故障被拒绝。完整 Rust release 回归 630 项通过、18 项显式忽略、0 项失败；没有调用真实设备或供应商。macOS 仅同步更新了接入代码，未在本机执行该平台运行时验证。

旧分包器用于样本对照时会保留大输入的数组容量，而新通道按 capacity 计费并限制单包。回归直接拼接旧分包器的尾包作为完整音频基准，避免把新通道限制强加给冻结的旧算法。性能对照使用此前保存的旧测试程序，不能将接上新通道的 legacy_push 当作完整旧版本。
