# 实时识别积压的内存与临时文件双重预算

## 根因与处理范围

文件投喂可以暂停等待识别，但麦克风和系统音频发送路径不能等待慢模型或网络。此前实时 ASR 输入仍使用无界内存队列；原生推理、模型初始化或网络消费落后时，音频会持续堆积。本次约束 ASR 输入队列，不修改采样内容、DSP、识别模型或供应商协议。

正常短队列保留原有内存传递，不创建临时文件或后台写盘线程。排队的驻留音频超过 2 MiB 后，新增音频交给按需创建的独立阻塞写盘线程，以最多 8 MiB 的文件段存放原始 f32 位值。发送路径只做计费、有限复制和入队，没有文件 I/O，也不等待消费者。单个原始输入暂时保留到入队完成，以便接收器关闭的竞态下仍能把原包还给采集层。

## 容量与所有权

以下均为每个识别会话的预算，不是应用总内存上限：

- 队列内和待写盘任务持有的浮点分配容量合计最多 64 MiB；使用 Vec.capacity() 计费。
- 逻辑积压（分配容量及消息包装）最多 512 MiB；消息最多 32768 个；单包分配最多 64 KiB。目前生产采集按最多 4096 样本分块。
- 临时文件段实际保留的数据另有 512 MiB 预算。已消费包可能与未消费包共用文件，所以不能只靠逻辑队列长度约束磁盘。
- 超限、线程启动失败、写入失败或文件不完整都使任务明确失败，不能静默丢音频后继续报告成功。
- 可暂停的文件输入仍使用 64 KiB 等待预算，不会因此落盘。

上述浮点预算不包含发送方持有的原包、入队时的短暂副本、已取出的处理包、消息元数据、线程栈、模型和系统文件缓存；消息数量与单包上限另行约束相关开销。多个会话的预算相加，不能把单会话上限当作全进程上限。

临时路径由文件段所有者持有，写入器、接收票据和读取器共享所有权，最后一个引用释放后删除。Windows 必须先关闭文件句柄，再释放路径所有者。取消优先于积压，接收器关闭票据后后台线程跳过未开始的写入并退出；已经进入操作系统的同步文件 I/O 不保证可立即中断。

## 异步与失败边界

Apple 的外层 select 可能放弃尚未完成的 recv future。已经取出的磁盘票据和异步读盘票据必须留在接收器 pending 字段，不能只保存在临时 future 中，否则下一次接收会丢包。异步接收的实际文件读取交给阻塞线程。

暂存失败同时设置原有取消标记，以便打断正在执行的 SDK 宿主操作。初始化失败和正常退出都发送结束事件；模型对比的结束处理必须保留此前的错误状态，且不得影响已替换的新会话。

## Windows 发布配置对照

使用合成 48 kHz 单声道 f32、4096 样本分包，不调用设备、网络或识别服务。每组在三个独立进程运行，取中位数。旧基线在测试内保留 cae5ec6 的实时队列包装、字节计费和释放通知算法；不是完整旧应用的端到端对照。双方预先初始化同一 Tokio 运行时。

积压场景按 100 倍实时速度、每 16 包一批注入，消费者等全部提交后才读取。此负载有意模拟长积压；测试里的统一注入节奏不是生产发送方法的等待逻辑。

30 分钟压力下，新路径最大观测驻留音频为 2.25 MiB，产生 41 个文件段；全部消费并退出后文件均删除，释放后私有提交中位数约 6.29 MiB。总耗时包含约 18 秒统一注入节奏，旧 18104.48 ms、新 18409.24 ms，不应据此宣称识别提速。过程读写量来自进程 I/O 计数器，包含经过系统缓存的请求，不等于物理磁盘实际读写量。系统文件缓存的独立归属未测，因此这里只证明测试进程私有提交下降，不能宣称整机物理内存减少相同数额。

短队列场景每次提交后立即消费，三档输入都无临时文件和音频磁盘读写。30 分钟等量数据快速处理的总耗时旧 85.47 ms、新 84.00 ms，峰值私有提交约 5.59 / 5.63 MiB，差异不足以宣称提速或退化。单次发送计时均值约 0.042 / 0.054 微秒，只用于观察本地路径开销，不代表多线程调度或设备实时延迟。

所有新旧场景的输出哈希一致：5 秒 f0af84c7eb7338d0、5 分钟 1b3394fe3e5a6775、30 分钟 50a2fbe6b5d2434e。回归另外覆盖 NaN 位型、正负无穷、负零、跨文件段顺序、尾部完成、多个生产者、反复取消、实际只读文件写入失败、截断后读取失败，以及异步接收 future 被放弃。

最终完整 Rust release 回归为 618 项通过、17 项性能/外部素材用例显式忽略、0 项失败。另复测 300 秒音频快速积压后的取消，停止消费耗时中位数 2.86 ms，取消后处理样本数为零；停止消费之后，后台缓冲和文件完整回收另耗时约 4.65 ms。30 分钟文件投喂路径仍保持 64 KiB 预算，峰值私有提交约 4.00 MiB、输出哈希 1b2e3ea68c5a2098，与此前一致。

复现：release 测试程序配合 scripts/measure-audio-performance.mjs，场景 asr-spool / asr-spool-legacy，短队列为 asr-short / asr-short-legacy；参数 --seconds 1800 --runs 3。JSON 保存程序 SHA256、内存峰值与释放后值、读写字节、文件段数量、驻留音频观测值、耗时和完整输出哈希。

## 仍需单独处理的边界

- 原始采集订阅队列与模型对比初始化期间的缓存还未在本轮限容，不能据此宣称整条音频管线已全部有界。
- 当前文件删除依赖正常析构；进程被强制终止或系统崩溃后的遗留清理尚未覆盖，不保证崩溃后无临时文件。
- macOS 运行时与真实设备/供应商未在这台 Windows 机器验证；本轮证据是本地合成数据与 Rust 回归，不是所有平台端到端认证。
