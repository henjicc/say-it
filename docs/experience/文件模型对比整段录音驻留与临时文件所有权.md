# 文件模型对比整段录音驻留与临时文件所有权

## 原因与处理

模型对比只要包含文件模型，原来就一直保留完整 f32 录音，停止后才写 PCM16 WAV。实时消费者已经完成开头补发后，这份数组仍继续扩容。导出的临时路径仅传给识别任务，正常完成和取消没有统一的文件所有者。

现在录音工作线程逐块写最终 WAV，沿用对比原有的截断量化，实际设备采样率不变。实时消费者接入前仍保留开头音频，同锁补发和登记保证每个消费者收到完整、顺序一致的输入；全部实时消费者登记后释放开头数组，文件模型独立使用写盘结果。固定写缓冲为 64 KiB，编码工作区为 16 KiB，磁盘 I/O 不持有对比状态锁。

停止先关闭采集、完整排空尾包，再更新文件头、flush 并交付结果。十秒排空超时、任务提前退出和写盘错误都进入失败收尾，释放麦克风租约与实时会话，不能用部分文件继续识别。取消和重置关闭结果接收端；未被接收的完成文件、未完成写入器均由所有权自动清理。

完成文件用 Arc 共享给各个实际文件识别任务，同时在任务登记期间保留一份。不能在界面收到“取消”或“完成”事件时直接删除：事件和取消标记可能早于供应商实际退出。最后一个实际任务退出后删除录音。用户上传的原文件没有此所有权，不会被删除。

## Windows 发布配置验证

本地合成 48 kHz 单声道输入，4096 样本分包，以最快速度注入；生产对比缓存逻辑和生产 WAV 写入器，旧分支保留原来的整段数组后导出行为。每组三个独立进程，下表取中位数。未打开真实麦克风、识别模型或网络服务，不是全应用端到端延迟。

| 音频长度 | 原峰值私有提交 | 新峰值私有提交 | 原总处理耗时 | 新总处理耗时 | 原停止写出 | 新停止收尾 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 5 秒 | 5.74 MiB | 3.82 MiB | 2.99 ms | 1.91 ms | 2.20 ms | 0.16 ms |
| 5 分钟 | 100.89 MiB | 3.82 MiB | 64.55 ms | 34.35 ms | 29.71 ms | 0.34 ms |
| 30 分钟 | 774.23 MiB | 3.82 MiB | 585.20 ms | 203.59 ms | 244.95 ms | 0.28 ms |

输出哈希新旧一致：5 秒 `ad4c8e4a0691ccc1`、5 分钟 `2ecd7d9b12881e31`、30 分钟 `676e55209e1873ce`。30 分钟输出仍为 172800044 字节，逻辑写入量仅从 172800044 增到 172800088 字节（重写 44 字节文件头）；计时阶段逻辑读取量为零。文件校验读取在计时结束之后。

存储成本提前发生在录音期间，因此中途取消也会写入部分数据。Windows 文件缓存仍会使用可回收页面，未强制同步物理磁盘，不能将进程私有提交降幅等同于整机物理内存降幅或冷磁盘性能。

回归覆盖迟到实时消费者、并发补发顺序、44.1 kHz 文件逐字节兼容、残留尾包、最后消费者退出清理、取消与重置后的文件回收、排空任务缺失/退出/错误。底层写入器既有测试覆盖磁盘写入、seek、flush 和容量上限失败。完整 Rust 发布配置回归：596 项通过，14 项性能测试显式忽略，0 项失败。

复现：构建 release 测试程序后，运行 `scripts/measure-audio-performance.mjs --scenario compare-file-storage --executable <测试程序> --output <结果.json> --seconds 1800 --runs 3`，旧路径选择 `compare-file-storage-legacy`。结果包含测试程序 SHA256、峰值、阶段内存、耗时、进程逻辑 I/O 字节数与文件哈希。

## 尚未覆盖

- 实时模型初始化期间的开头积压、麦克风输入队列、各模型队列仍需单独建立预算；慢磁盘可能造成输入排队，不能称整条录音链路已完全有界。
- macOS 运行时未验证；本轮没有模拟实际设备长时间采集或调用真实识别服务。
- 进程被强制终止不能运行 Drop；崩溃遗留文件的启动清扫另行处理。
