# Windows 高频截屏的耗时与 CAPTUREBLT 指针闪烁

适用：需要每隔几百毫秒截一次屏幕（判断窗口内容有没有变、截光标附近的小块区域）时，例如动态上下文（`active_app_context/dynamic_monitor.rs`）。

## 实测（本机 Windows 10，debug 构建，耗时几乎全在 GDI 里）

| 截取方式 | 平均耗时 |
| --- | --- |
| 整个前台窗口 `StretchBlt` 缩到长边 48 像素，`HALFTONE` | 约 72 ms |
| 同上，改用 `COLORONCOLOR`（最近邻） | 约 44 ms |
| 光标周围 480×120 原尺寸 `BitBlt` | 约 17～20 ms |
| 这块 480×120 交给内置 PP-OCR 识别 | 约 25 ms |

- 耗时主要花在从屏幕设备上下文读回像素上，和源区域面积有关，缩得再小也省不了多少。
- 截一张缩略图就要几十毫秒，不能放在每 33ms 采一次光标的循环里，否则会漏掉很短的单击、双击。要放到单独的线程，间隔也要拉长（动态上下文用 500ms）。

## CAPTUREBLT

截给 OCR 的整窗截图带 `CAPTUREBLT`，这样能截到分层窗口。但这个标志在部分系统上会让鼠标指针闪一下，高频截取时很明显，所以缩略图和小块区域截图都不带它（`screen_capture.rs` 的 `Quality::Quick`）。这时也截不到本应用的听写胶囊，正好不会干扰「内容变了没有」的判断。

## 判断内容变化

- 比的是缩略图里明显变了（亮度差超过 24）的像素占比，超过 6% 才算变了。输入框里多几个字、光标闪烁都不到这个比例。
- 还要求连续两张缩略图相同（滚动停下了）才去读一次。一直在播放的视频永远不会算「停下」，所以不会被反复 OCR。
