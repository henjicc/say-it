# Rust 音频调校内部 Base64 往返导致峰值内存放大

## 原因与边界

前端迁移为领域快照后，`process_offline` 的调用方已经是 Rust `AudioLabRuntime`，
但结果仍沿用旧的 `PCM → 字节 → Base64 → 字节 → PCM` 表示。
降噪、增益处理也各自分配整段音频，导致任务峰值显著高于最终需要保留的原声和处理声。

领域内部直接传递 `Vec<f32>` 所有权；波形和统计仍使用原有快照，音频不会传回前端。
降噪按原来的 480 样本帧处理，先复制一帧输入到独立数组再原地写回；尾帧仍补零，
干湿混合仍读取本帧原声。增益和限幅原地应用，保持浮点运算与算法顺序。

## 验证方法

先保留优化前的 release 测试程序及其 DLL，再构建优化后的测试程序：

```powershell
node scripts/run-rust-tests.mjs --release --no-run
node scripts/measure-audio-performance.mjs --executable <测试程序.exe> --output <结果.json>
node scripts/measure-audio-performance.mjs --executable <测试程序.exe> --output <降噪结果.json> --seconds 3 --denoise
```

测试程序路径以 Cargo 输出为准。Windows 中文目录构建的 NASM 问题见
[既有记录](本机release构建NASM不支持中文路径.md)。每次采样启动独立进程，使用
`PROCESS_MEMORY_COUNTERS_EX` 读取私有提交峰值，避免同一进程之前的任务污染峰值。
结果包含二进制 SHA-256、输入时长、降噪开关、输出校验值、统计和回收后内存。

2026-09-24，本机 Windows x64 release，300 秒 48 kHz 单声道合成音频，关闭降噪：

| 指标（三次采样中位数） | 优化前复测 | 优化后 |
| --- | ---: | ---: |
| 进程私有提交峰值 | 302.34 MiB | 120.70 MiB |
| 调校处理耗时（包含波形摘要） | 516.66 ms | 394.30 ms |
| 全量输出校验值 | `3ccc040ff5928c85` | `3ccc040ff5928c85` |

3 秒开启降噪的全量输出校验值也相同：`85cb3c851ff27b5c`。
回归覆盖空音频、静音、单样本、整帧和非整帧尾部、16/44.1/48 kHz 输入及原始素材保留。
这是独立音频链路的结果，不代表整机空闲内存降幅；原声和处理声仍随时长增长，
后续长音频流式化需要独立解决这一部分，不能据此宣称缓冲已经有界。


## 后续：素材暂存与分块离线 DSP

去掉 Base64 后仍同时保留整段原声与处理声，Vec 扩容也会放大长录音占用。现在每份素材最多保留 2 MiB 浮点容量，超过后以原始 f32 位值转存，不使用有损量化。每份原声或处理声有 512 MiB 暂存上限，容量、磁盘写入或读取失败均报告错误；这是每份素材的预算，不是整个应用的统一上限。处理中还会暂时保留上一版处理结果，成功后替换，失败时保留旧结果。

离线处理不能直接改用实时处理器：两者的增益策略和重采样相位计算不同。新实现按绝对输出索引进行原有线性插值，固定 480 样本降噪帧与尾帧补零，持续复用均衡器状态。第一遍测量原声/降噪均衡后的全段响度并暂存浮点输出；第二遍使用同一全段增益，原地应用限幅并测量输出。全量历史响度保持原有算法，不改成近似直方图或短时间窗。

处理读取素材快照，不在整个 DSP 期间占住会话锁。内存分支共享不可变数据、追加时写时复制；文件分支通过固定前缀长度与绝对偏移读取。处理任务串行调度，只允许当前最新参数发布结果，旧任务在下一个处理块取消；前端也丢弃晚到的旧结果和旧取消错误。录音写入和重处理在阻塞工作线程运行。波形按原有 860 段的精确边界计算，素材不变时复用缓存。

试听 WAV 按块量化写出，同一素材重复试听复用同一文件。Windows 的浮点暂存与试听文件均使用句柄关闭删除：浮点文件禁止按路径重新打开；试听文件仅开放共享读/删除，供资产协议读取。所有者销毁或进程强制退出后，由系统回收文件。正在播放的文件通过独立持有关系保留到下一次试听切换或应用退出，参数/素材替换不会打断播放器后续的分段读取；最多额外保留一份当前播放文件。Unix 浮点文件仍在打开后立即 unlink；试听文件必须保留可读取路径，当前只保证正常析构清理，异常退出不能套用 Windows 的保证，macOS 运行时尚未验证。

测试涵盖 8/16/44.1/48/96 kHz、单样本、帧边界、跨处理块、跨内存/文件阈值、静音、负零、降噪混合、语音门、均衡和限幅。所有输出样本和 LUFS/峰值与冻结旧算法逐位比较；另验证读取截断文件、只读文件写入失败、容量失败、快照隔离、取消、试听缓存与删除。强制退出回归增加可按路径读取的试听文件场景，三轮共 15 次独立子进程退出。

回收测试必须同时等待文件消失与预算归零：文件句柄先关闭、随后字段析构才归还文件预算，两者不是同一个原子动作。仅等待路径消失后立刻断言计数，可能把正常析构的中间状态误报为泄漏。

| --- | ---: | ---: | ---: | ---: |
| 5 秒，关闭降噪 | 6.46 MiB | 7.15 MiB | 7.21 ms | 7.29 ms |
| 5 分钟，关闭降噪 | 120.73 MiB | 9.53 MiB | 391.07 ms | 573.90 ms |

四组全量输出哈希分别为 3012f36bbafcb46d、3ccc040ff5928c85、a5aa5010ea97c0a5、da0a2326b0592019，前后全部一致。5 秒不落盘、句柄数不增加，峰值增加约 0.69 MiB，处理时间无明显差异；分块同时测量输入与均衡后的响度需要两份响度计，固定开销不能忽略。

30 分钟素材完成处理并继续保留时，测试进程私有提交约 3.98 MiB；但原声与处理声仍占约 659.18 MiB 临时文件，不能将这项结果描述成整机总内存减少了同样数额。记录阶段写入约 329.59 MiB，快速注入全部素材耗时约 1010 ms；处理阶段读取约 1318.36 MiB、写入约 659.18 MiB，包含波形摘要但不含测试专用哈希读取。计数来自进程 I/O 请求，包含系统缓存，不等于物理磁盘流量；系统文件缓存归属未单独测量。长素材用额外 I/O 与约 0.88 秒处理时间换取固定工作内存，并让处理可取消且不独占会话锁，不应宣称离线运算本身提速。

30 分钟句柄数为 166 → 168 → 166，短素材为 166 → 166 → 166。报告 audio-lab-storage-before/after-*.json 与保存程序 audio-lab-storage-tests.exe 位于工作区，包含程序 SHA256。另有前端 Mock 回归验证晚到旧结果不覆盖新参数、旧取消不显示错误、当前真实失败仍上报；无真实 API 或设备请求。

## 完整应用内的补充验证（2026-09-24）

使用隔离的 `performance-acceptance` 构建，执行 `scripts/measure-app-lifecycle.ps1 -Executable <验收程序> -OutputDirectory <新目录> -Scenario audio-lab`。只将设备输入替换为分块生成的固定信号；正式的后端重处理命令、阻塞线程调度、状态快照、WAV 试听文件仍在实际 Tauri 应用中运行。主 WebView 保持关闭，避免把界面成本混入音频处理结果。

`工作区/performance/audio-lab-app-1` 连续三轮每轮注入 30 分钟 48 kHz 素材，关闭降噪处理，随后以一秒素材替换并经过默认降噪和试听路径：

- 三轮长素材处理 2881.45 / 2964.80 / 3063.69 ms；全量输出均为 `a5aa5010ea97c0a5`，与上文冻结算法基线一致。
- 冷启动私有提交 6.51 MiB；处理及哈希阶段观测峰值分别 8.16 / 8.79 / 7.84 MiB；最终闲置保留一秒素材和当前试听文件为 7.47 MiB。
- 三次短素材替换后句柄均为 215，没有逐轮增长；停止后的有效 CPU 采样没有测得增量。处理阶段平均 CPU 约 4.13%～4.16%（本机全部逻辑处理器归一化），不是单核百分比。
- 空素材处理被拒绝后能继续正常处理；样本数量、时长、统计及波形完整，旧试听文件在新试听替换后消失；程序正常退出，无已知残留进程。

约一秒的外部采样不是瞬时峰值测量；该轮没有测系统文件缓存或物理磁盘流量，长素材仍使用前述临时文件，不能把进程提交量当作整机成本。短素材替换是正常生命周期，不调用测试专用清空或工作集修剪。该场景未覆盖设备实时采集、播放器实际发声或处理中的取消；这些边界不能用本次成功结果代替。
