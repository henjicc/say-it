# macOS 悬浮窗拖拽触发 Reopen 误开主窗口

## 现象

主窗口已经关闭、应用仍在后台运行时，按住并拖动不可聚焦的悬浮窗，macOS 可能向 Tauri 派发 `RunEvent::Reopen`。如果处理逻辑只判断 `has_visible_windows == false`，就会把这次悬浮窗交互误判成用户点击 Dock 图标，重新创建主窗口。

## 处理原则

- `Reopen` 不能只凭 `has_visible_windows` 决定是否打开主窗口。
- 处理事件时可以读取鼠标的全局物理坐标，以及悬浮窗的物理位置和尺寸，作为按下瞬间的第一层保护。
- 仅靠鼠标命中不可靠：原生拖拽期间 `Reopen` 可能延迟到鼠标已经移动后才到达，坐标也可能处于悬浮窗范围外。
- 应由后端命令先设置一段短暂的 `Reopen` 抑制期，再调用原生窗口拖拽，保证两个动作的执行顺序。
- 悬浮窗持续收到移动事件时延长抑制期，覆盖长时间拖拽；拖拽停止后让抑制期自动过期，不影响之后点击 Dock 打开主窗口。
- 坐标命中判断必须使用同一坐标系，并覆盖负坐标显示器和右、下边界的半开区间。

这样不会改变悬浮窗自身的点击、拖拽和听写逻辑，也不会阻断用户从 Dock 或托盘主动打开主窗口。
