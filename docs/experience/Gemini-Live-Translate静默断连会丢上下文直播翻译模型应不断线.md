# Gemini Live Translate 静默断连会丢上下文，直播翻译模型应不断线

## 现象

实时字幕选 Gemini Live Translate 时，译文在连续说话时正常，但每次停顿几秒
后再说话，译文质量明显下降：主语、指代经常翻错，像是模型忘了前面说过什么。

## 根因

字幕默认开启静音断连（`subtitle_silence_disconnect_ms` 默认 5000）：原始音频
消费者检测到超过 5 秒无声就调用 `disconnect_for_silence`，拆掉整个 ASR 会话，
下次有声再开一个全新会话。Live API 的对话上下文只存在于会话内，重连即清零。

日语对此格外敏感：主语、宾语经常省略，只能靠前文推断；上下文一丢，译文
只能靠猜。

## 处理

`application/subtitles/mod.rs` 的静默断连判定抽成
`should_disconnect_for_silence`，自带翻译的识别模型（`live_translate_asr()`）
直接返回不断线：静默时只停发有效语音、不断会话，上下文一直保留。普通模型
保持原有行为（静默超时即断开，省连接占用）。

取舍：不断线的代价是会话保持期间的连接占用；对直播翻译模型，准确度优先
于这点节省。

## 验证方式

- 单元测试覆盖判定函数：直播翻译模型长静默不断线；普通模型超时才断线、
  未超时不断线、无会话不断线、无语音记录不断线。
- 真机验证：选 Gemini Live Translate、翻译模型保持“无”，说一段带主语的日
  语，停顿 10 秒以上再说省略主语的后续句，译文里的指代应与前文一致；且
  停顿期间不应出现会话重连导致的译文中断。

## 教训

- 给实时翻译模型接静默省电/省连接的逻辑前，先确认上下文是不是存在会话里；
  存在会话里的上下文，断线就等于失忆。
- 排查“越往后翻越不准”时，先看会话是不是在静默时被拆过，再怀疑模型本身。
