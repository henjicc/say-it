# Rust 变量遮蔽不释放互斥锁：智能处理进入前永久等待

## 现象与根因

ASR 已完成，但悬浮球停在处理中，主窗口读取供应商配置也可能一起无响应；网络请求尚未发起，因此网络超时不能救场。

`selected_profile` 先用 `let settings = state.providers.lock()?` 持有锁，再用同名变量保存规范化的配置副本。Rust 的变量遮蔽不会立即销毁旧 `MutexGuard`。后面的 `drop(settings)` 只销毁新副本，执行配置读取函数再次获取 `providers` 锁时发生同线程死锁。

## 防线

- 使用已有的 `read_provider_settings` 获取拥有所有权的配置快照；锁在 helper 返回前释放。
- 不把“变量换了名字/被遮蔽”当作锁已释放。必须检查 guard 的真实作用域和下游函数会获取哪些锁。
- 回归测试应运行真实调用链，并用测试线程与限时接收判断是否返回，不用网络请求模拟这类故障。本次测试修改前稳定超时，修改后返回配置且 `try_lock` 成功。
- 不用延长网络超时、增加 loading 动画或无限重试来掩盖锁死。
