# 主窗口销毁重建时 Ready 与打开请求竞态

主窗口使用“关闭即销毁、需要时重建”的策略后，窗口对象、前端 Ready 握手和用户打开请求可能以不同顺序到达。

- 平台预创建窗口可能在 setup 完成登记前发送 Ready。状态机必须先记住已就绪，后续登记时按启动策略决定显示或保持隐藏，不能重新退回 Creating 等待第二次握手。
- 主窗口处于 Closing 时收到打开请求，不能只返回 AwaitReady。销毁完成后必须保留并重放该请求，否则一次托盘、Dock 或悬浮球点击会被关闭完成动作清掉。
- `show()` 与 `set_focus()` 的错误不能静默忽略；调用入口应收到失败，日志才能区分“窗口未创建”和“已创建但显示/激活失败”。
- 回归测试至少覆盖 Ready 早于初始登记，以及打开请求落在 Closing 阶段这两种顺序。
