# 原生悬浮窗开发约定

适用于听写胶囊、悬浮球、实时字幕条的原生实现：`src-tauri/crates/overlay-*` 与 `src-tauri/src/desktop/native_*.rs`。

本文件只记录已经落地的结构与约束。

## workspace 与子 crate

`src-tauri` 是 Cargo workspace，target 与 `Cargo.lock` 仍在 `src-tauri/` 下由全部成员共用：

| 包 | 目录 | 职责 |
|---|---|---|
| `say-it` | `src-tauri/` | 主应用；平台分发、Windows 原生悬浮窗后端与 Tauri 胶水在 `src/desktop/` |
| `sayit-overlay-core` | `src-tauri/crates/overlay-core` | 平台无关层：状态机、动画、布局、"画什么"与跨平台契约，只实现一份 |
| `sayit-overlay-macos` | `src-tauri/crates/overlay-macos` | macOS 后端：用 objc2 系 crate 驱动 core 的模型；`lib.rs` 首行 `#![cfg(target_os = "macos")]` |

依赖边界：

- `sayit-overlay-core` 不得依赖 `windows`、`objc2*`、`tauri` 或主 crate `say-it`，平台中立由编译边界保证。
- `sayit-overlay-macos` 只依赖 core 与 objc2 系 crate，不依赖 tauri、主 crate 或任何带 C 构建脚本的 crate。
- 主 crate 依赖 core；macOS 目标下另外依赖 `sayit-overlay-macos`。

## 共用层模块与平台分发

`crates/overlay-core/src/lib.rs` 的模块表固定如下，状态机、动画、布局与“画什么”只在 core 实现一份：

| 模块 | 职责 |
|---|---|
| `geom` | DIP 与 DesktopPx 几何、颜色、笔触、变换、命中与玻璃形状；`snap_out_px` 按设备像素外扩 |
| `canvas` | `Canvas` 绘制与 `TextEngine` 排版契约；文字索引统一为 UTF-16，布局句柄不要求 Send |
| `window` | `OverlayModel` / `PointerModel`、命令副作用、指针与系统事件、`FrameClock` 帧时钟 |
| `look` | `Profile`、主题与玻璃外观；WindowsLegacy 保留现行颜色预乘，Css 使用 straight alpha |
| `screen` | Quartz 点、DesktopPx、Cocoa 与指针坐标换算；混合缩放重叠区按屏 id hint 消歧，窗口按中心选屏 |
| `anim` | `Transition` 入退场动画，`tick(now)` 显式接收时钟，方向改变后首帧 dt 为 0 |
| `svg` | SVG 路径解析，输出绝对坐标段，供各平台构建路径 |
| `blur` | 预乘 BGRA/RGBA 像素共用的 `image::imageops::fast_blur` 包装 |
| `indicator` | 听写胶囊模型、通知截止时间、动画、波形与绘制；始终点击穿透 |
| `orb` | 悬浮球点击/右键动作、拖拽阈值、波形纯逻辑与应用动作枚举，窗口模型的归属模块 |
| `subtitle` | 字幕配置与默认值、颜色/文本/布局纯逻辑与应用动作枚举，窗口模型的归属模块 |
| `present` | Mac 主线程提交队列的归属模块，当前为空桩 |
| `testing` | 仅测试可见的 RecordingCanvas 与 FakeText；用固定度量验证模型行为 |

- `canvas.rs`、`window.rs`、`look.rs`、`screen.rs` 是平台共同依赖的契约；Canvas / TextEngine 后续仅允许新增带默认实现的方法，签名变更需先协调调用方。
- 模型输出有序 `Vec<WindowOp<A>>`，宿主执行副作用时不得持有模型借用；主线程指针层只读 Copy 命中快照，渲染状态与文本布局留在所属线程。
- `FrameClock` 在启动时固定首帧截止时间，查询或重复同步不能推迟它；首帧 dt 为 16ms。`Transition` 使用自己的时钟基准，方向改变后首帧 dt 为 0。
- `desktop/native_common.rs` 统一开关解析与 `native_overlay_set_look` 外观分发；外观仅转交 Mac 桥，Windows 原生窗口固定使用 `Look::WINDOWS_LEGACY`。
- `desktop/native_mac/` 仅在 macOS 编译：`mod.rs` 提供 `ensure_started` / `set_look`，`indicator.rs`、`orb.rs`、`subtitle.rs` 接收各窗口公开 API 并保留动作回调；当前均为无操作桩，查询返回 `None` / `false`。三个 `native_*.rs` 保持公开 API 路径稳定，按 cfg 分发 Windows 实现或 Mac 桥。
- `native_subtitle_reference_size()` 返回字幕百分比布局的逻辑参考尺寸；Windows 返回 `None`，由调用方继续测量主显示器；Mac 转交字幕桥，当前桩返回 `None`。
- `SAYIT_NATIVE_INDICATOR` / `SAYIT_NATIVE_ORB` / `SAYIT_NATIVE_SUBTITLE`：值为 `0` 时关闭并回退 WebView；其它任何已设置值（含空字符串）开启；未设置取平台默认。目前仅 Windows 默认开启，macOS 默认关闭。各窗口通过自己的 `OnceLock` 在首次读取时缓存开关，修改环境变量需重启进程。

## overlay-macos 的依赖策略

- objc2 系 crate 的版本跟随 `Cargo.lock` 中 tao/wry 引入的同一系列，不单独升级；新增或调整依赖后确认锁文件没有出现第二个版本。
- 一律 `default-features = false`，只显式列出实际用到的 feature。
- 禁止开启 `objc2` 的 `exception`/`catch-all`：它们用 cc 编译 C，Windows 本机就无法再交叉检查本 crate；也不依赖 `objc2::exception::catch`，改为进入 AppKit/CoreAnimation 前校验几何（`is_finite`、夹取）。

## overlay-macos 的线程约束

- 所有 CoreGraphics/CoreText 绘制只在该 crate 的单一渲染线程执行。
- 渲染线程禁止同步等待主线程：不得 `dispatch_sync`，不得调用 `SayItRunOnMainThread` 系列；主线程需要的状态通过 `Mutex`/原子共享。

## overlay-macos 的绘制与排版

- `cg::CgCanvas` 实现 `Canvas`：sRGB、预乘 BGRA 位图，DIP 左上原点；`finish` 产出不可变 `CGImage`，`pixels` 返回顶行优先的紧密像素。静态 SVG 路径按 `(key, 填充/描边)` 缓存在渲染线程，椭圆弧由 core `svg::arc_to_cubics` 转换。
- `ct::CtText` 实现 `TextEngine`，布局句柄为 `Rc<CtLayout>`，不得跨线程传递。手动断行保留 UTF-16 范围，固定行高与基线按契约计算；着色只重建对应行的绘制 run，不改变缓存断行。命名字体按族名核对后回退至 `PingFang SC`、系统 UI 字体，语言固定为 `zh-Hans`。
- macOS 离屏绘制测试（包括排版测试）共用 `cg::CG_TEST_LOCK`，避免 CoreGraphics 并发抗锯齿串色（FB25211753）；新增测试必须使用同一把锁。

## Windows 后端

- `desktop/native_win/mod.rs` 承载窗口线程、DIB、时钟与 DPI 接缝及平台绘图工具；`d2d.rs` 实现完整 Canvas / TextEngine；`host.rs` 提供通用窗口过程和有序副作用执行；`indicator.rs` 是胶囊的窗口特性与分发胶水。
- `host.rs` 的状态保存在 `RefCell` 中，只在生成副作用或绘入 DIB 时借用；执行 WindowOp、ShowWindow、UpdateLayeredWindow、SetWindowPos、捕获切换、系统拖拽或应用动作前必须结束借用。`surface.rs::draw_frame` 返回独立持有当帧 DIB 的上屏请求，由宿主在借用外执行；`surface.render` 暂供未迁移的悬浮球和字幕使用。
- 系统拖拽前同步帧定时器，返回后补发 `SystemDragEnded`；`WinWindow::after_ops` 只更新跨线程镜像，不调用窗口系统。胶囊通知使用模型的 3500ms 截止时间，不注册第二个定时器。
- Windows 胶囊固定用 `Look::WINDOWS_LEGACY`，所有颜色经 `look.color`；D2D 接收画刷颜色后不再预乘。绘制顺序、公式类型、结合顺序与常量保持现行像素；DrawText 转布局必须先验证像素，只有不一致时才增带默认实现的 Canvas 方法。
- `desktop/native_win/snapshot/` 为三窗共享的离屏像素回归网；悬浮球与字幕暂由各自 `native_*.rs` 的 Windows 实现调用此后端。

## Windows 像素快照

重构原生悬浮窗时的逐字节回归网：用真实窗口过程驱动听写胶囊、悬浮球、实时字幕条的关键状态（含动画中途、悬停与按钮、DPI 96/120/144/168），离屏截取 DIB 与上屏参数，与本机基准逐字节比对。场景在 `src-tauri/src/desktop/native_win/snapshot/`，测试函数名一律以 `native_snapshot_` 开头。

- 改动 `native_*.rs`、Windows 后端、core 模型或任一 Canvas 实现后，verify 必须全绿：

  ```powershell
  $env:SAYIT_OVERLAY_SNAPSHOTS='verify'; npm run test:rust -- --bin say-it native_snapshot; Remove-Item Env:SAYIT_OVERLAY_SNAPSHOTS
  ```

- `SAYIT_OVERLAY_SNAPSHOTS=record` 写基准（每个用例一张 `<case>@<dpi>.png`，外加 `manifest.txt` 记录 `case x y w h alpha`）；`verify` 比对像素与上屏参数，不一致时写 `<case>.actual.png`、`<case>.diff.png` 并汇总全部失败；未设置时为冒烟（CI 默认），只断言该有内容的帧有不透明像素且整窗不透明度大于 0、该透明的帧整窗透明。record/verify 先断言场景用到的字体存在；每个窗口都会打印比对的用例数，为 0 时失败。
- 基准目录默认 `测试/native-overlay-snapshots/<window>/`，不入库；`SAYIT_OVERLAY_SNAPSHOT_DIR` 可改指其他目录，worktree 中必须指向主检出的 `测试/native-overlay-snapshots`。
- 基准只对本机有效：依赖本机字体、系统版本（D2D 软件光栅与 DirectWrite）、文本渲染设置与显示器布局，所以不进 CI 比对。胶囊和字幕的位置取自主显示器，显示设置或任务栏变化会让清单里的位置失败；像素全部一致时在主检出重录即可。
- 只有经用户确认的有意视觉变更才在主检出 record，并且单独提交；修正原有视觉缺陷（如胶囊与悬浮球颜色的双重预乘）也属于有意视觉变更。worktree 中只 verify，不 record。
- 动画计时一律走 `native_overlay::overlay_now()`，DPI 一律走 `window_dpi()`/`system_dpi()`，不直接调用 `Instant::now()`、`elapsed()` 或 `GetDpiFor*`，否则快照无法注入时钟与 DPI，动画帧会随真实时间漂移。

## 验证命令

- core 快测：`cargo test --manifest-path src-tauri/Cargo.toml -p sayit-overlay-core`。
- Mac 后端本机类型检查：`npm run check:mac-overlay`（首次需 `rustup target add aarch64-apple-darwin`）。它只检查 `sayit-overlay-macos`（含测试目标），产物放在 `<CARGO_TARGET_DIR 或 src-tauri/target>/mac-check`，与主构建分开，可与 Windows 构建并行；Rust 工具链变更时 `test:rust`/`tauri:dev` 的缓存回收会整体删除该目录。
- 本机检查覆盖不到选择子编码、链接与运行期行为：推送后看 CI `verify (macos-15)` 的 "Test overlay crates" 步骤；Mac 运行时、视觉与交互只能由用户真机验证。
- 主 crate 本身无法在 Windows 上做 Mac 检查（ring、libsqlite3-sys 等需要 Apple SDK），所以 Mac 代码尽量放进 `sayit-overlay-macos`，主 crate 只留薄转发。
